Video 1: Introduction to Java: Why Java Exists

The series goal is to understand Java's internals using first principles, going beyond syntax. This video answers one question: why was Java created when C and C++ already existed? Java was built to fix three problems, and it wins on three points: it is Portable, Simple, and Secure.

The Era Before Java (1980s–1990s)

C and its successor C++ dominated programming. They were popular because they were:

  • Fast.
  • Relatively simple: English-like syntax compared with the languages before them.
  • Low-level: close to the hardware, talking almost directly to the processor with few layers of abstraction. In a high-level language like Python, much of the work happens internally. In C/C++, you do most of it yourself.

Compiler & Machine Code (basics)

  • A computer understands only binary (0s and 1s). This is machine code.
  • A compiler is itself a piece of software. It translates source code (English-like) into machine code.
  • Evolution: Machine code (writing raw 0/1 sequences) → Assembly (a few English words like MOV, closely tied to hardware) → C/C++ (English-like, and the compiler does the translation).

Problem 1 with C/C++: Portability

C/C++ compile source code directly into machine code for one specific platform. That binary won't run on a different platform. To run the same code elsewhere, you must recompile it for each platform. So C/C++ are platform-dependent (not portable).

What is a Platform?

⭐ Interview Important: Platform = Processor + Operating System.
e.g. P1 = Intel x86 + Windows, P2 = ARM + macOS.

Why Does the Same Source Code Produce Different Binaries?

Both parts of the platform affect the generated machine code:

1. Operating System → different system libraries

  • Your program can't print, read/write files, or allocate memory on its own. It has to ask the OS.
  • When you write cout / printf, the compiled output uses the OS's system libraries: precompiled methods that the OS provides. Their code ends up in (or is linked into) your binary.
  • Windows and macOS expose different system methods for the same task (e.g. a hypothetical WriteToConsole vs WriteThere). So the binaries differ.

2. Processor → different ISA (Instruction Set Architecture)

  • A processor (CPU) is physical hardware made of billions to trillions of transistors. Each transistor is either on (1, current flows) or off (0).
  • Intel and ARM place their transistors, circuits, and pins differently. The binary needed to make even "add two numbers" happen at the hardware level is therefore different on each.
  • Between a program and the processor sits the ISA. It defines how basic operations like add, load, store, and jump are expressed for that processor.
⭐ Interview Important: ISA = Instruction Set Architecture
Think of the ISA as the "grammar" of a processor. Different processors (x86 vs ARM) understand different grammars, so they need different machine code for the same program.
Platform componentWhat differsEffect on binary
Operating SystemSystem libraries / system calls (console, files, memory)Different OS-level code linked in
ProcessorISA: the instruction "grammar"Different machine instructions

Every language before Java compiled straight to machine code, so all of them were platform-dependent.

Problem 2: Simplicity

C++ was simpler than older languages, but some features still made it complex:

  • Pointers
  • Multiple inheritance
  • Manual memory management, especially deallocation

Problem 3: Security

C++ was less secure. A more secure language was needed, which became urgent once code started to travel over the internet (see below).

⭐ Interview Important: Why Java was created (three problems it solved):
1. Portability: C/C++ are platform-dependent.
2. Simplicity: pointers, multiple inheritance, and manual deallocation make C++ complex.
3. Security: C/C++ programs were less secure.

Solution 1: Java is Portable, via Bytecode + JVM

Analogy: C/C++ is like having to learn Mandarin before visiting China and Spanish before visiting Spain. Java's approach: you speak one language, and in each country a translator converts it into the local language.

  • The Java compiler (javac) does not compile to machine code. It compiles to an intermediate code called bytecode, which is not 0s and 1s machine code.
  • Hello.java → compile → Hello.class (the bytecode file; .java becomes .class).
  • The bytecode is the same for every platform.
  • The JVM (Java Virtual Machine) is the translator. It's software installed on each platform that reads the bytecode step by step and converts it into that platform's machine instructions.
⭐ Interview Important: Is the JVM platform-independent? No.
Bytecode is platform-independent. The JVM is platform-dependent. Each platform needs its own JVM, because the JVM has to know that platform's OS (how to call its system libraries) and its processor (how to speak its ISA). Java's trade-off: write one JVM per platform once, and then any bytecode runs everywhere. (In the analogy, you keep a separate translator in each country, and each one understands your language.)
⭐ Interview Important: WORA = Write Once, Run Anywhere
Java is portable, or platform-independent. You compile once to bytecode and run it on any platform that has a JVM installed.

Why did portability matter so much?

  • New devices / embedded systems (set-top boxes, TVs, and later smart devices): the goal was to build an app once and run it on every Java-enabled device, i.e. one that has a JVM.
  • The internet: backend code runs on servers, and each server is a computer with its own platform. Without portability, every new server with a different platform would need a recompile.
  • Speed stopped being decisive: processors became fast enough that closeness to the hardware mattered less than having a general-purpose language that runs everywhere. Java is slower than C++ but much faster than Python.

Solution 2: Java is Simple

Java removed C++'s complex features:

  • No pointers
  • No multiple inheritance (for classes)
  • No manual memory deallocation (handled automatically, covered later in the series)

Solution 3: Java is Secure, via the JVM Sandbox

Java spread quickly and was used on both ends of the web:

  • Servlets (backend): Java programs on the server that act like an API, fetching data and writing to the database.
  • Applets (frontend): lightweight code sent over the internet that runs inside the user's browser, for simple forms, calculators, and displaying server output. Java came before JavaScript.

The risk: clicking a link could download an applet and run it on your machine. A malicious applet could request system permissions, steal or copy data, or crash the system.

The fix: the JVM runs bytecode in a secured, restricted environment and denies unnecessary or harmful permissions. This is the Sandbox Model.

⭐ Interview Important: The JVM alone solves two of the three problems: portability (bytecode → platform machine code) and security (the sandbox). Simplicity comes from the language design and syntax.
  • Applets are obsolete now that JavaScript runs the frontend. The speaker wasn't sure of the exact JDK version (10 or 11). For the record: applets were deprecated in JDK 9, browser-plugin and appletviewer support was removed in JDK 11, and the Applet API was later marked for removal.
  • Side note: JavaScript was named after Java only because Java was the most popular language at the time. The two languages are unrelated.

Could C/C++ Be Made Platform-Independent?

  • Yes, in theory. The same idea applies: compile to an intermediate code, then run it on a platform-specific virtual machine.
  • It wasn't done for C++ because it was never meant to be. C++'s purpose is to stay close to the hardware and fast.
  • Microsoft applied the idea successfully to C#, a close relative of C++ built as an alternative to Java. C# compiles to an intermediate language that the .NET runtime executes, much like bytecode on the JVM.
  • Modern languages that came after Java, such as C# and Python, follow the same intermediate-code + VM principle in their own ways. Java popularized platform independence.

• What is a platform? → Processor + OS.
• Why does the same C++ code produce different binaries? → Different OS system libraries + different processor ISA.
• What is an ISA? → Instruction Set Architecture, the processor's "grammar" for add/load/store/jump.
• What is bytecode? → Platform-independent intermediate code in a .class file, produced by javac.
• Is the JVM platform-independent? → No. The JVM is platform-specific. Bytecode is platform-independent.
• What is WORA? → Write Once, Run Anywhere.
• How is Java secure? → The JVM sandbox model runs bytecode in a restricted environment.
• What did Java remove from C++? → Pointers, multiple inheritance, and manual memory deallocation.

In the past you could download a JRE by itself. Today you just install the JDK (Oracle stopped shipping a separate JRE from JDK 11 onward).

Compiler vs Interpreter

Both translate code from one form to another, usually into machine code. A compiler doesn't have to output machine code: javac turns Java into bytecode. The difference between them is how much they translate at once.

  • Compiled language, e.g. C/C++: the compiler turns source directly into machine code.
  • Interpreted language, e.g. Python: an interpreter sits in between. Python has extra internal steps, not covered here.
  • Neither approach is strictly better. Each has trade-offs.
⭐ Interview Important: Is Java compiled or interpreted? Both.
1. Compiled: javac compiles source → bytecode.
2. Interpreted (+ JIT-compiled): the JVM converts bytecode → machine code at runtime.

Inside the JVM: Interpreter + JIT Compiler

Why only an interpreter at first (1990s)?

  • Java already has an extra step (source → bytecode) that it pays for portability. Putting a second full compile inside the JVM would slow down startup even more.
  • Hardware back then was weak: slow CPUs, limited RAM, slow disks.
  • An interpreter lets a program start running as soon as possible, because each line is converted and executed immediately.

Modern JVM: a hybrid model

Once hardware improved, a JIT (Just-In-Time) compiler, which is highly optimized, was added alongside the interpreter. It did not replace it, because compiling everything up front would still be slower to start.

  • Hot code (frequently executed parts) → the JIT compiler compiles it straight to native machine code, so it doesn't get re-interpreted line by line over and over.
  • Cold code (rarely used parts) → the interpreter keeps converting and running it line by line.
  • Note: the JVM finds hot code at runtime by profiling, e.g. counting how often methods and loops execute. The speaker described it as the JVM "reading the bytecode" to decide.
⭐ Interview Important: What is the JIT compiler?
JIT = Just-In-Time compiler, part of the JVM. It compiles frequently used (hot) bytecode into native machine code while the program runs, and the interpreter handles the rest. This hybrid gets both fast startup and fast execution.
  • Java vs C++ speed: C++ is still slightly faster because it compiles straight to machine code, while Java has an extra stage. With modern hardware and the JIT, the gap is now negligible. The small cost is the trade-off for portability, simplicity, and security.
⭐ Interview Important: Responsibilities of the JVM
1. Convert bytecode → machine code using the interpreter + JIT compiler.
2. Security through the sandbox model: bytecode (possibly downloaded from anywhere) never runs directly on the system. It runs inside the JVM, which monitors and blocks unauthorized access such as deleting files or planting viruses or trojans. The JVM itself is software running on your system.
3. Garbage collection (covered in a later lecture).

Class Libraries (what the JRE adds)

  • Your code contains only your business logic. Everyday operations like printing to the console, reading files, and so on are prewritten internal code supplied by the language. These are the class libraries.
  • They're similar to C/C++'s printf / cout via #include <iostream>. In Java you bring in library classes with import statements.
  • Without them, the JVM couldn't run even a line that prints to the screen. That's why the JRE is the minimum needed to run a program.

What the JDK adds

  • Compiler (javac): source → bytecode.
  • Debugger: pauses a program line by line so you can inspect values at each step.
  • Javadoc: generates documentation. There are other tools too.

With the JDK installed, you can write code in any editor or IDE (Notepad for tiny programs; VS Code or IntelliJ for real ones), compile it, and run it.

Video 3: Variables, Data Types, Keywords & Comments

Variables

  • A program exists to do something: print, calculate, and so on. Once it needs to work with values (e.g. a calculator adding two numbers), those values have to be stored in memory (RAM).
  • A variable is a named container, i.e. a memory location, that holds a value. Internally the value is stored in binary.
  • Memory has regions like stack and heap. Those are covered later.
  • Naming: use descriptive names (firstNumber, secondNumber) instead of x, y, so the name tells you what the variable holds.

Identifier & Literal

  • Identifier: the name used to identify the container, e.g. firstNumber. Variable, method, and class names are all identifiers.
  • Literal: the actual value written in the code and stored in the container, e.g. 10, 'a', false.
  • These terms (variable, identifier, literal, keyword) mean the same thing in every programming language.

Syntax of a Variable

⭐ Interview Important: Java is statically typed.
You must declare a variable's data type in the code, before compilation, and the compiler checks every use against it. In a dynamically typed language like Python, the type is decided at runtime.

Black-box model of learning: for now, treat the boilerplate (public class Demo, public static void main(String[] args)) as a black box. Focus only on the code inside main's curly braces. Its internals are covered later.

Data Types

⭐ Interview Important: Java has 8 primitive data types. byte, short, int, long, float, double, char, boolean.

1. Integer Types

All four hold whole numbers. They differ only in size (width in bits), and therefore in range, i.e. how large a number they can hold. A value that fits a smaller type also fits every larger one.

TypeWidthRange
byte8 bits−128 to 127

long64 bits≈ ±9.22 × 1018 (quintillions)

For numbers beyond long, Java has a special class (BigInteger, covered later).

Binary basics (why the ranges are what they are)

  • Decimal is base 10 (digits 0–9, place values 1, 10, 100, …). Binary is base 2 (digits 0 and 1, place values 20=1, 21=2, 22=4, 23=8, …).
  • Examples: 2 = 10, 3 = 11, 4 = 100, 10 = 1010 (8 + 2).
  • An n-bit type has n positions. Unused high positions are filled with 0s.
  • With n bits you get 2n unique combinations. Unsigned, the largest value is 2n − 1 (e.g. 3 bits → max 7 = 111, and 8 bits → max 255).
  • Java integers are signed: the 2n combinations are split between negatives and non-negatives, so the range is −2n−1 to 2n−1 − 1. For a byte that's −128 to 127, not 0 to 255.
⭐ Interview Important: range formula for a signed n-bit integer
−2n−1 to 2n−1 − 1. For byte: −27 to 27−1 = −128 to 127. The positive side is one smaller because 0 takes one of the non-negative slots.
Note: all numeric primitives are signed. char is the exception: it's an unsigned 16-bit type (0 to 65,535).

⭐ Interview Important: prefer double over float.
• double has far more precision and range. Anything a float can hold, a double can too.
• Older processors were optimized for float. Modern hardware is optimized for double, so there's no speed benefit to using float.
• Java's built-in math methods (Math.sin, Math.cos, …) return double.
• A decimal literal like 10.54 is a double by default. Storing it in a float requires the f suffix (10.54f). Otherwise you get "Type mismatch: cannot convert from double to float".
• Float is almost never used in production code.
• Correction to the video: for money, don't use float or double. Binary floating point can't represent values like 0.1 exactly. Use BigDecimal instead.

3. Character Type: char

  • Holds a single character, written in single quotes: char alphabet = 'a';. The quotes tell the compiler it's a character and not an identifier.
  • Computers only store numbers, so each character is mapped to an integer, and that integer is stored in binary (e.g. 'A' = 65, 'a' = 97).
  • When you read the value back, the data type decides how the stored bits are interpreted. If the type is char, 65 is shown as 'A'. If it's int, the same bits are shown as 65.
  • ASCII (used by C/C++): covers English letters, digits, and common symbols, with codes 0–127 (7 bits, usually stored in 8). It has no codes for characters like Hindi क or ग, Chinese, Greek, Tamil, and so on.
  • Java wanted to be used worldwide, so it adopted Unicode: a standard that assigns an integer to characters from every language. That's why a Java char is 16 bits.
⭐ Interview Important: char in Java is 16 bits (2 bytes) and Unicode-based. In C/C++, char is 8 bits and ASCII-based.

4. Boolean Type: boolean

  • Only two possible values: true or false. Example: boolean b = false;
⭐ Interview Important: In C/C++, any non-zero number means true and 0 means false. In Java, a boolean can only be true or false. boolean b = 0; or = 1; is a compile error, and an int can't be used as a condition.

Declaration vs Definition

int y;       // declaration: reserves a 32-bit container named y
y = 4;       // definition / assignment: gives it a literal value (e.g. later, from user input)

Values usually aren't hardcoded. They often come from user input, so declaring first and assigning later is common. (In standard Java terminology this is declaration vs initialization/assignment.)

Keywords

  • Keywords are reserved words that Java uses for itself, e.g. class, public, static, void, int. They can't be used as identifiers (names for variables, methods, and so on). int class = 5; is an error.
  • The video says Java has 68 keywords. The exact count depends on the Java version and on whether you include contextual words like var and record and the literals true/false/null.
  • System, out, and println are not keywords. They're names of a class, a field, and a method.
⭐ Interview Important: goto and const are reserved keywords in Java but are never used. They were reserved because they exist in C/C++ and the designers thought Java might need them, but Java was completed without them.

Video 4: How Negative & Floating-Point Numbers Are Stored

A positive integer is stored as its plain binary. This video covers the other two cases: negative integers, which use 2's complement, and floating-point numbers, which use IEEE 754. It also explains why some decimals come back slightly wrong.

The Hidden Problem with Floats

float f = 0.7f;
System.out.println(f);          // 0.7
System.out.printf("%.20f%n", f); // 0.69999998807907100000   ← not 0.7!

float g = 8.125f;
System.out.printf("%.20f%n", g); // 8.12500000000000000000   ← exact
  • %.20f means "print this floating-point value to 20 decimal places".
  • println hides the error. Float.toString prints the shortest decimal that maps back to the same float, which is "0.7". The value actually in memory is 0.699999988079071044921875. (The video describes this as Java "rounding it off".)
  • So 8.125 is stored exactly, but 0.7 is not. The reason is explained below.

Decimal → Binary (integer part)

Keep dividing by 2 and write down each remainder. Then read the remainders bottom to top.

42 ÷ 2 = 21  r 0
21 ÷ 2 = 10  r 1
10 ÷ 2 =  5  r 0
 5 ÷ 2 =  2  r 1
 2 ÷ 2 =  1  r 0
 1 → 1              read upward → 101010 → padded to 8 bits: 00101010  (32 + 8 + 2)

Adding zeros on the left never changes an integer's value, so padding to the type's width is safe.

Negative Integers: 2's Complement

Take byte b = -42; (8 bits, range −128 to 127). To store it:

  1. Ignore the sign and write the binary of +42.
  2. 1's complement: invert every bit (0→1, 1→0).
  3. 2's complement: add 1 to that result. This is what gets stored.

Reading it back (System.out.println(b))

  • The MSB is 1, so the number is negative. The same two steps recover the magnitude: invert (00101001), then add 1 (00101010) = 42. Put the minus sign on to get −42.
  • Shortcut: in 2's complement, the MSB has weight −128 instead of +128. For 11010110: −128 + 64 + 16 + 4 + 2 = −42.
  • Correction: the video says the Java compiler does this when printing. The literal -42 is encoded at compile time, but printing happens at runtime. The JVM and library code (Integer.toString) turn the bits back into text.

MSB & LSB

  • MSB (Most Significant Bit) is the leftmost bit. It carries the most weight, like the thousands digit in 2321, where +1 there adds 1000.
  • LSB (Least Significant Bit) is the rightmost bit. +1 there changes the value by only 1.
  • In signed integers, the MSB is the sign bit: 0 → positive (or zero), 1 → negative.
⭐ Interview Important: why can't a positive byte have MSB = 1?
The largest byte is +127 = 01111111. Setting the MSB alone (10000000) would be 128 unsigned, which is outside the byte range. So every positive value has MSB 0. Negatives get their MSB flipped to 1 by the inversion step, and the +1 only changes it back in the zero case (see below). In practice, 10000000 is −128.

Why 2's Complement and Not Just 1's Complement?

With 1's complement, zero would have two representations. Adding 1 removes the second one.

⭐ Interview Important: advantages of 2's complement
• Only one zero. 1's complement has both +0 (00000000) and −0 (11111111). This is the reason the video gives.
• Not covered in the video: the freed pattern gives one extra negative number, which is why the range is −128 to +127 (asymmetric).
• Not covered in the video: the CPU can use the same adder circuit for addition and subtraction (a − b = a + (−b)), with no special sign handling.
• Java identity: -x == ~x + 1. For example, ~42 + 1 is -42.

Not covered in the video: because of the asymmetric range, Math.abs(Integer.MIN_VALUE) returns -2147483648. +2,147,483,648 doesn't fit in an int, so it overflows back to itself. This is a classic trick question.

Floating-Point Numbers: IEEE 754 Layout

Java's float and double follow the IEEE 754 standard. The bits are split into three fields.

Storing a Float: 4 Steps (example: 8.125f)

  1. Convert to binary. The integer part 8 is 1000. For the fractional part, multiply by 2 repeatedly, take the integer digit each time, and read top to bottom: 
    0.125 × 2 = 0.25  → 0
0.25  × 2 = 0.5   → 0
0.5   × 2 = 1.0   → 1   (fraction is now 0 → stop)
0.125 = .001   →   8.125 = 1000.001₂
  2. Normalize to 1.x × 2exp (binary scientific notation). Moving the point 3 places left gives 1.000001 × 23. The base is 2, not 10, because this is binary. (The video writes "1.0001" at one point, but the mantissa it stores, 000001, matches the correct 1.000001.)
  3. Add the bias to the exponent: 3 + 127 = 130 = 10000010.
  4. Place the fields in memory: sign = 0 (positive), exponent = 10000010, and mantissa = the bits after "1.", padded with zeros to 23 bits. The leading 1 is not stored, because every normalized number starts with it (the "implicit/hidden bit").

Retrieving it: the decode formula

value = (−1)sign × (1 + mantissa) × 2(exponent − bias)
  • (−1)0 = 1 keeps the value positive, and (−1)1 = −1 makes it negative.
  • 1 + restores the hidden leading 1, and − bias undoes step 3.
  • Mantissa bits after the point have weights 2−1, 2−2, 2−3, and so on. For 8.125, only the 6th bit is set: 2−6 = 1/64 = 0.015625.
  • So: 1 × (1 + 0.015625) × 2130−127 = 1.015625 × 8 = 8.125. The value comes back exactly.

Why 0.7f Is Not Exact

0.7 × 2 = 1.4 → 1
0.4 × 2 = 0.8 → 0
0.8 × 2 = 1.6 → 1
0.6 × 2 = 1.2 → 1
0.2 × 2 = 0.4 → 0   ← 0.4 again: the cycle 0.4 → 0.8 → 0.6 → 0.2 repeats forever
0.4 × 2 = 0.8 → 0
...
0.7 = 0.1 0110 0110 0110 …₂   (never terminates)
  1. Normalize: 1.0110 0110 0110… × 2−1.
  2. Exponent: −1 + 127 = 126 = 01111110. (The bias is what lets a negative exponent be stored as a positive number.)
  3. The mantissa has only 23 bits, so the infinite pattern is cut off.
  • Decoding those 23 bits gives the nearest float to 0.7, not 0.7 itself. That's the 0.69999998… seen with %.20f.
  • Precise version: IEEE 754 rounds to the nearest representable value, which is not quite the same as truncating. For 0.7 the next bit is 0, so rounding and truncation give the same result here.
⭐ Interview Important: which decimals are exact?
A fraction is exact in binary only if it's a sum of powers of ½ (denominator a power of 2) and fits in the mantissa: 0.5, 0.25, 0.125, 8.125 ✓. Numbers like 0.1, 0.2, and 0.7 repeat forever in binary, so they are always approximations, in both float and double. Classic example: 0.1 + 0.2 prints 0.30000000000000004, so 0.1 + 0.2 == 0.3 is false.
→ Never compare floats/doubles with ==. Compare with a tolerance (Math.abs(a - b) < 1e-9).
→ For money or exact decimals, use BigDecimal (covered later in the series).

Not covered in the video: create a BigDecimal from a String, e.g. new BigDecimal("0.7"). new BigDecimal(0.7) captures the double's binary error: 0.69999999999999995559….

The Bias

  • The exponent can be negative (0.7 needs 2−1). IEEE 754 doesn't store a signed exponent. Instead it adds a fixed bias so the stored field is always a non-negative, unsigned number. This makes the hardware simpler and lets floats be compared almost like integers.
  • Formula: bias = 2(k−1) − 1, where k is the number of exponent bits.
    • float: k = 8 → 27 − 1 = 127
    • double: k = 11 → 210 − 1 = 1023
  • 8 exponent bits hold stored values 0–255, and 127 sits at the middle. The video says the exact choice of 127 over 128 is a hardware detail it doesn't cover.
  • Correction: stored exponents 0 and 255 are reserved. 0 is used for zero and very tiny "subnormal" numbers, and 255 for Infinity and NaN. So normal float exponents run from −126 to +127, not down to −127 as the video implies.

double in Memory

  • It works exactly the same as float, but uses 64 bits: 1 sign + 11 exponent + 52 mantissa, with bias 1023.
  • More mantissa bits make the error smaller, but numbers like 0.7 are still not exact. double only pushes the error further out.

Not covered in the video: unlike integers, IEEE floats do have −0.0, because the sign bit is separate. 0.0 == -0.0 is true, but Double.valueOf(0.0).equals(-0.0) is false, and 1 / -0.0 is -Infinity.

⭐ Quick Revision / Likely Interview Questions
• How are negative integers stored in Java? → 2's complement: binary of |x|, invert all bits, add 1. For example, −42 as a byte = 11010110.
• How does the CPU know a value is negative? → MSB (sign bit) = 1.
• Why 2's complement over 1's complement? → Only one zero (no −0), one extra negative (−128..127), and the same adder works for subtraction.
• Math.abs(Integer.MIN_VALUE)? → Still negative (overflow).
• float layout? → 1 sign + 8 exponent + 23 mantissa, bias 127. double → 1 + 11 + 52, bias 1023.
• Decode formula? → (−1)S × (1 + M) × 2(E − bias).
• Why is the leading 1 not stored? → Every normalized number is 1.x, so it's implicit, which gives a free extra bit of precision.
• Why is there a bias? → To store negative exponents as unsigned numbers. Formula 2k−1 − 1.
• Why does printf("%.20f", 0.7f) show 0.6999…? → 0.7 repeats forever in binary, so the mantissa is cut off. println just prints the shortest round-tripping decimal.
• Is 0.1 + 0.2 == 0.3? → false. Use a tolerance, or BigDecimal (with the String constructor) for exact decimals.

Video 5: Type Conversion, Casting & Type Promotion

Type conversion means putting a value of one primitive type into a variable of another type, e.g. byte → int or int → byte. There are two kinds.

KindWho does itDirectionAlso called

1. Implicit (Widening) Conversion

⭐ Interview Important: rule for implicit conversion
The destination type must be wider than the source type. Every value the source can hold then fits in the destination, so no data can be lost and Java converts silently.
byte b = 24;
int i;
i = b;                   // OK: byte (8-bit, −128..127) always fits in int (32-bit)
System.out.println(i);   // 24

char c = 'a';
int x = c;               // OK: char (16-bit) → int (32-bit)
System.out.println(x);   // 97, the Unicode value of 'a'

A char is stored internally as its Unicode number, so it widens to int like any number. The char type only tells Java to show the character instead of the number when printing.

  • Not covered in the video: int/long → float and long → double are implicit but can lose precision, because the mantissa is smaller than 32 or 64 bits. (float) 16777217 becomes 1.6777216E7. The range still fits, so Java allows it.
  • Not covered in the video: byte b = 24; compiles even though 24 is an int literal, because it's a compile-time constant that fits in a byte. The same works for final int k = 10; byte bb = k;. A non-final int variable needs a cast.

2. Explicit (Narrowing) Conversion: Casting

int i = 300;
byte b = i;            // ✗ compile error: "incompatible types: possible lossy conversion from int to byte"
byte b = (byte) i;     // ✓ cast: "I know data may be lost, do it anyway"
System.out.println(b); // 44

Syntax: (targetType) value. The cast tells the compiler the narrowing is intentional. Other narrowing examples: long → int and double → float.

Why 300 becomes 44

⭐ Interview Important: shortcut for narrowing an int to a byte
The video's shortcut is 300 % 256 = 44. % is the modulo (remainder) operator, and 256 = 28 is the number of values a byte can hold.
Correction: that shortcut only works when the remainder is ≤ 127. The kept 8 bits are read as a signed 2's-complement byte, so if the remainder is 128–255, subtract 256. For example, (byte) 200 is −56, not 200, because 200 = 11001000 and its MSB is 1.

3. Truncating Conversion (float/double → integer)

This is a special case of narrowing.

float f = 15.678f;
int i = f;          // ✗ error, even though float and int are both 32 bits
int i = (int) f;    // ✓ 15  (the fractional part is chopped off)
  • A cast is required even though both are 32-bit, because int can't hold a fractional part.
  • It truncates toward zero, it does not round: (int) 15.678f is 15 and (int) -15.9 is −15. To round, use Math.round(15.678f), which gives 16.
  • Not covered in the video: out-of-range values clamp to the limit ((int) 1e20f is Integer.MAX_VALUE), and NaN becomes 0.

boolean: No Conversion At All

boolean bool = false;
int i = bool;        // ✗ incompatible types
int i = (int) bool;  // ✗ still an error, even with a cast
⭐ Interview Important: boolean can't be converted to or from any other type, implicitly or with a cast. true/false are not numbers in Java, unlike C/C++ where 0 means false.

Automatic Type Promotion (in expressions)

byte a = 50, b = 40, c = 100;
int i = a * b / c;   // 50*40 = 2000 (outside byte range!) → /100 = 20 → fits in int ✓

During arithmetic, Java automatically promotes byte/short/char operands to int. Otherwise an intermediate result like 2000 wouldn't fit in a byte.

The classic surprise

byte b = 50;
b = b * 2;            // ✗ error: possible lossy conversion from int to byte
                      //   b is promoted to int, so b * 2 is an int (100), and int → byte needs a cast
b = (byte) (b * 2);   // ✓ 100
b = (byte) b * 2;     // ✗ still an error: the cast applies only to b, then * 2 makes it an int again
  • The parentheses are needed because the cast has higher precedence than *. Operators are covered in a later video.
  • Not covered in the video: compound assignment includes a hidden cast, so b *= 2; compiles. This can overflow silently: with b = 100, b += 100 gives −56.

Type Promotion Rules

  1. byte, short, char → int in any arithmetic expression, even byte + byte.
  2. If any operand is long, the operation is done in long.
  3. If any operand is float, the operation is done in float. Float beats long because it covers a wider range of values.
  4. If any operand is double, the operation is done in double.

In short, the result takes the widest type involved, and the minimum is int. Priority: double > float > long > int.

Not covered in the video: because promotion is per operation, i / c is integer division (the fraction is dropped) before it ever meets the float. Another classic: 1 / 2 * 2.0 is 0.0, because 1 / 2 is int division and gives 0 first.

⭐ Quick Revision / Likely Interview Questions
• Implicit vs explicit conversion? → Widening happens automatically (destination wider than source). Narrowing needs a cast (type).
• Widening order? → byte → short → int → long → float → double. char → int.
• (byte) 300? → 44 (the lowest 8 bits). (byte) 200? → −56 (the value is read as signed).
• (int) 15.678f? → 15 (truncated, not rounded). Use Math.round to round.
• Can boolean be cast to int? → No, not even explicitly.
• Why does byte b = 50; b = b * 2; fail? → b is promoted to int, so the result is an int. Fix it with (byte)(b * 2), or use b *= 2, which has a hidden cast.
• Result type of byte + byte? → int.
• Result type of a mixed expression? → The widest operand type, and at least int (double > float > long > int).
• Can widening lose data? → The range always fits, but int/long → float and long → double can lose precision.

2. Increment / Decrement: ++ --

i++ is i = i + 1 (the same as i += 1), and i-- is i = i - 1. They exist because stepping by 1 is very common, e.g. in loops and array indexes. There is no ** or // operator.

Not covered in the video: a classic trick question is int j = 5; j = j++;. The result is still 5. The old value (5) is saved, j becomes 6, and then the assignment writes the saved 5 back.

3. Relational Operators: == != < > <= >=

  • Relational operators compare two values and always produce a boolean (true/false).
  • a == b asks "is a equal to b?". a = b is assignment: it copies b into a.
  • <= is true if either less than or equal holds, so with a = b = 10, a <= b is true and a < b is false.
  • Code that produces a value, like a == b or a + b, is called an expression.
int a = 5, b = 10;

boolean d = (a != b);   // true

Not covered in the video: in Java, if (a = b) with ints doesn't compile, because an int isn't a boolean. This prevents the classic C bug of assigning where you meant to compare. (It does compile for booleans: if (flag = true).)

4. Bitwise Operators: & | ^ ~

These work on the individual bits of integer values, and the result is an integer.

  • AND is 1 only if both bits are 1. OR is 1 if at least one is 1. XOR is 1 if there's an odd number of 1s (the bits differ). NOT (unary) flips every bit.
  • A table like this is called a truth table. These are the same logic gates the CPU is built from.

⭐ Interview Important: why ~2 is −3
An int has 32 bits, so NOT flips all the leading zeros to 1 as well. The result starts with 1, which makes it negative in 2's complement. Shortcut: ~x == -x - 1.

5. Shift Operators: << >> >>>

Left shift <<

⭐ Interview Important: shifts only happen on int or long
Because of type promotion, a byte/short/char is promoted to int first. The shift happens on all 32 bits, and a cast back to byte just truncates to the lowest 8 bits. So b = b << 1; doesn't compile for a byte. You need b = (byte)(b << 1);.

Why this matters: take byte b = 1; and shift it left 7 times. As a byte it looks like 10000000 = −128. Shift it once more:

  • With a byte result it looks like shifting "stops working" and stays 0. With int i = b << 1; you see the real value, −256, and further shifts give −512, −1024, and so on.
  • When an int or long is widened, the upper bits are filled with copies of the sign bit (0 for positive, 1 for negative). This keeps the value the same.

How far can you shift? (the shift distance is taken mod 32)

1 << 30   // 1073741824      (the 1 is at bit 30, just below the sign bit)
1 << 31   // -2147483648     = Integer.MIN_VALUE (the 1 is now the sign bit)
1 << 32   // 1   ← not 0!   (32 % 32 = 0, so it's a shift by 0)
1 << 33   // 2               (33 % 32 = 1)
⭐ Interview Important: the shift distance is masked
For an int, Java uses only the low 5 bits of the shift distance, i.e. n % 32, so the useful range is 0–31. Moving a bit from the LSB (bit 0) to the MSB (bit 31) takes at most 31 shifts, and anything beyond that is pointless.
Correction: for a long it's n % 64 (0–63), not 32 as the video implies. 1L << 32 is 4294967296, and 1L << 64 is 1.

Correction: the video calls Integer.MIN_VALUE "negative infinity". It is the smallest int, −2,147,483,648. Algorithms often use it as a "−∞" placeholder, but it isn't a real infinity (only float and double have -Infinity).

Right shifts: >> (signed) vs >>> (unsigned / zero-fill)

  • x >> n moves bits right. The LSBs fall off, and the new MSBs are copies of the sign bit, so the sign is kept. This is roughly x / 2n: 8 → 4 → 2 → 1, and −128 → −64 → −32.
  • x >>> n always fills with 0, whatever the sign (the video calls it the "dumb shift"). A negative number becomes a large positive one. It's useful when the bits are just data with no sign, e.g. pixel values, hashes, or unsigned math.
⭐ Correction: >>> on a byte does NOT give +64
The video's 8-bit example says −128 >>> 1 is +64. In Java, the byte is first promoted to int (1111…10000000). The zero-fill happens at bit 31, so it gives 2147483584, and casting back to a byte keeps 11000000 = −64, the same as >>. Verified: (byte)(b >>> 1) with b = -128 prints −64. >>> only behaves as "unsigned" on the full int or long.
  • Right shifts on byte/short look correct after a cast, because >> drops the LSBs and the kept low 8 bits still match. Left shifts are where the truncation surprises you.
  • The mod-32 (int) and mod-64 (long) rule applies to right shifts as well.

6. Logical Operators: && || !

Logical operators work on boolean expressions, not bits. They use the same truth table with true/false in place of 1/0: && is true only if both sides are true, || is true if at least one is, and ! flips the value.

int a = 5, b = 10, c = 15;
boolean d = (a < b) && (b < c);   // true
boolean e = (a < b) || (a > c);   // true

Short-circuit evaluation

  • Once the left side decides the answer, Java skips the right side. This is used to guard risky checks, e.g. obj != null && obj.isValid(), so the second part never runs on null (null is covered later).
⭐ Interview Important: how to avoid short-circuiting
& and | also work on boolean operands. They give the same logical result but always evaluate both sides. The difference shows up when the right side has a side effect: 
int c = 0;

This is rarely used in real code (about 99% of the time you want &&/||), but it's a favourite interview question. Also, ^ on booleans is logical XOR, and ~ works only on integers, while ! works only on booleans.

7. Assignment Operator: =

  • = puts the right-hand value into the left-hand variable. It's evaluated right to left and has the lowest precedence, so everything on the right is computed first.
  • Assignments can be chained: a = b = c = 10; assigns 10 to c, then c's value to b, then b's value to a.

Correction: the video says int a = b = c = 10; declares all three. It doesn't. It declares only a, and it fails with "cannot find symbol: b" unless b and c already exist. Correct forms are int a, b, c; a = b = c = 10; or int a = 10, b = 10, c = 10;.

Flow of Control

Flow of control is the order in which statements run. By default it is sequential: line 1, then line 2, then line 3. Some keywords change that order. Java has three kinds:

1. if and if-else

int i = 9;
if (i % 2 == 0) {            // condition MUST evaluate to a boolean
    System.out.println("i is even");
} else {                     // runs only when the condition is false
    System.out.println("i is odd");
}
  • The expression inside if ( … ) must be a boolean (true or false). It can combine operators, e.g. if (i > 5 && i < 10).
  • A plain if means "run this block or skip it". if-else means "exactly one of the two blocks runs".
  • Without else, two separate ifs are independent, so both can run. The video's first demo printed both "i is 5" and "i is not 5" for this reason.
  • Odd/even check: i % 2 == 0 means even.
  • Braces are optional for a single statement, but best practice is to always use them.
  • Style (not in the video): if (b == true) can simply be written if (b).

2. Nested if

if (i > 5) {
    if (i < 10) { … }   // inner if
    else { … }          // belongs to the inner if
} else { … }            // belongs to the outer if
  • An else always pairs with the nearest preceding unmatched if.
  • Every if may or may not have its own else.
  • Java has no limit on nesting depth, but good practice is 2 levels at most for readability. You can often flatten nesting with &&: if (i > 5 && i < 10).
  • Nested-if trace from the video: with i = 8, i > 5 and i < 10 are both true, and the innermost i == 7 is false. The outer else blocks still don't run, because their own ifs were true.
⭐ Interview Important: the dangling else (not covered in the video) 
int x = 12;
if (x > 5)
    if (x < 10) System.out.println("5-10");
else System.out.println("dangling else ran");   // prints! The indentation lies
Without braces, this else attaches to the inner if (x < 10), not the outer one. That's another reason to always use braces.

3. if-else-if Ladder

int age = 50;
if (age > 80)       System.out.println("You are very old");
else if (age > 60)  System.out.println("You are old");
else if (age > 40)  System.out.println("You are becoming old");   // ← this runs
else if (age > 20)  System.out.println("You are young");          // never checked
else                System.out.println("You are a child");        // final fallback
  • This handles more than two choices. Conditions are checked top to bottom. The first true one runs, and control leaves the whole ladder without checking the rest.
  • The final else is optional and runs only if nothing matched.
  • The ladder matters: if these were separate ifs, age 50 would print both "becoming old" (> 40) and "young" (> 20). Order the conditions from most to least specific.

4. switch Statement

int i = 3;
switch (i) {                 // compares i against each case label
    case 1:
        System.out.println("i is 1");
        break;
    case 2:
        System.out.println("i is 2");
        break;
    case 3:
        System.out.println("i is 3");
        break;
    default:                 // like the final else: nothing matched
        System.out.println("i is greater than 3");
        break;
}

break and fall-through

  • break exits the switch. Without break, execution falls through into the next case's code, without checking its label, and keeps going until it hits a break or the end.
  • The video demo removed every break with i = 1, and it printed "i is 1", "i is 2", "i is 3", and the default message.
  • Fall-through exists on purpose, for when several cases should share code or run cumulatively. The most common use (not in the video) is grouping labels: case 1: case 2: case 3: System.out.println("small"); break;.

switch rules and limitations

  • The selector must be byte, short, char, int (or their wrapper classes), an enum, or a String (since JDK 7).
  • Not allowed: long, float, double, boolean. switch (i > 4) fails because the selector is boolean, and switch (someLong) fails with "selector type long is not allowed".
  • No duplicate case labels: two case 1: labels give a compile error. An if-else-if ladder does allow a repeated condition. The second one is simply never reached.
  • Case labels must be compile-time constants (not in the video).
  • JDK 14+ greatly enhanced switch with case 1 -> … arrow labels (no fall-through) and switch expressions that return a value. This is covered later. The classic switch is still fully supported.
  • switch statements can be nested (a switch inside a case), like nested ifs. Again, avoid deep nesting.

switch vs if-else-if Ladder

switchif-else-if ladder
What it can testOnly equality against constant valuesAny boolean condition: >, <, ranges, &&…
Selector typesbyte/short/char/int, enum, StringAnything that gives a boolean
Duplicate conditionsCompile errorAllowed (later ones are unreachable)
How it finds the matchJumps via a table: O(1) or O(log n)Checks conditions one by one: O(n)

So switch exists because it is more efficient for many equality checks, and the ladder exists because switch can't express ranges or complex conditions.

Why switch Is Faster: Jump Tables (tableswitch vs lookupswitch)

The compiler doesn't turn a switch into a chain of comparisons. It generates a jump table in the bytecode, in one of two forms:

BytecodeWhenHow it worksCost
tableswitchCase values are dense (close together, e.g. 1, 2, 3)An array-like table from low to high. The target is found by index (i − low). Anything outside the range goes to default.O(1)
lookupswitchCase values are sparse (far apart, e.g. 1, 1000, 100000)Only the existing keys, sorted, with their targets. The JVM searches them, typically with binary search.O(log n)
  • Sparse values would make a tableswitch huge (100,000 slots, almost all empty), so the compiler picks the compact form instead.
  • Both forms beat the ladder's O(n) when there are many cases.

Checked with javap -c on real code:

switch(i) { case 1: … case 2: … case 3: … default: … }
  → tableswitch  { // 1 to 3
        1: 28   2: 31   3: 34   default: 37 }

switch(i) { case 1: … case 1000: … case 100000: … default: … }
  → lookupswitch { // 3
        1: 36   1000: 39   100000: 42   default: 45 }
  • Correction: the video draws default as a slot inside the table. It is really a separate target, used when the value is outside the table's range or isn't one of its keys.
  • Correction: the choice is a cost heuristic in javac (table size vs. search time), not strictly "dense means tableswitch". A dense switch with only 2 cases still compiled to lookupswitch.
  • For a handful of cases the speed difference is negligible, and the JIT may optimize either form. Choose switch mainly for clarity when many equality checks run on one value.
  • Not covered in the video: a String switch first switches on hashCode() and then confirms the match with equals().

Video 8: Loops (Iteration) & Jump Statements

A loop runs a block of code repeatedly while a condition stays true. Each pass is one iteration. Java has three loops: while, do-while, and for. It has two jump statements for use inside loops: break and continue.

Why loops: printing 1 to 10 with ten println calls (or println(i); i++; ten times) doesn't scale. A loop writes it once.

1. while Loop

int i = 1;
while (i <= 10) {           // condition must be a boolean, checked BEFORE every iteration
    System.out.println(i);
    i++;                    // update. Forget it and the loop never ends
}                           // prints 1..10, then the condition fails at i = 11
// Reverse: start i = 10, use while (i >= 1), and i--
  • Braces are optional for a single statement, but then only that one statement is in the loop. Always use braces.
  • If the condition never becomes false, you get an infinite loop. It runs until you kill the program.

Trap: increment inside the condition

int i = 1;
while (i++ <= 10) System.out.print(i + " ");   // prints 2 3 … 11 (!)
int i = 0;
while (i++ < 10)  System.out.print(i + " ");   // prints 1 2 … 10 ✓

Postfix i++ compares the old value and increments before the body runs, so the body sees the new value. To fix it, start one lower and use < instead of <= (see prefix vs postfix in Video 6).

2. do-while Loop

int i = 11;
do {
    System.out.println(i);   // runs once and prints 11, even though 11 <= 10 is false
    i++;
} while (i <= 10);           // ← semicolon required here
⭐ Interview Important: while vs do-while
while is entry-controlled: it checks first, so the body may run 0 times. do-while is exit-controlled: it checks after, so the body always runs at least once.
Classic use case for do-while: a menu (Play / Load saved game / Exit). You must show the menu once before knowing the user's choice, and you repeat until they pick Exit.

3. for Loop

for (int i = 1; i <= 10; i++) {      // (init; condition; update)
    System.out.println(i);
}
for (int i = 10; i >= 1; i--) { … }  // reverse
  • Declare the loop variable inside for (int i …) when it's only needed in the loop. Its scope is then just the loop, so it can't be used after the loop ends (compile error: "cannot find symbol"). Declare it before the loop if you need it afterwards.
  • All three parts are optional, but both semicolons are required: for (;;) is an infinite loop.
  • Comma-separated variables: for (int i = 1, j = 1; i <= 10 && j <= 5; i++, j += 2).
    • Several variables of the same type can be declared, and each can be updated its own way (i++, j += 2, k *= 2).
    • The condition can't use a comma (that's a syntax error). Combine conditions with && or ||.
    • With &&, the loop stops as soon as either condition fails. With ||, it stops only when both fail.
  • The condition can be any boolean, not just a counter check. For example, for (…; flag == true; …) with flag set to false inside an if ends the loop from within.
  • The for-each loop (enhanced for) is covered with arrays and strings.

Infinite Loops & Empty Bodies

while (true) { … }           for (;;) { … }          for (int i = 1; i < 10; ) { … }   // no update
int i = 5;  while (i < 10) { }   // empty body: i never changes, so it never ends

Not covered in the video, but common traps:

  • A stray semicolon: while (i < 3); makes the ; the whole (empty) body, so the program hangs. Verified: it ran until the timeout killed it.
  • Any statement after while (true) { } (with no break) is a compile error: "unreachable statement". The compiler knows a constant-true loop never ends. The video's while (i < 10) { } still compiles because i isn't a constant.

Why Loop Counters Are int (Not byte/short)

  • Most loops would fit in a byte or short, but the convention is always int (or long when needed). Arithmetic promotes byte/short to int anyway (Video 5). In the JVM, a local byte or short takes a full 32-bit slot, so there's no memory saving.
  • Not covered in the video: for (byte b = 0; b < 200; b++) never ends. b++ wraps from 127 to −128, so b < 200 is always true. Verified: after 300 iterations b was 44 and still going.

Nested Loops

for (int i = 1; i <= 5; i++) {        // outer: which ROW
    for (int j = 1; j <= i; j++) {    // inner: how many stars in this row (depends on i)
        System.out.print("* ");       // print() stays on the same line
    }
    System.out.println();             // new line after each row
}
*
* *
* * *
* * * *
* * * * *
  • For every iteration of the outer loop, the inner loop runs completely. The outer loop can't move on until the inner one finishes.
  • print vs println: println adds a newline after printing, and print doesn't. A bare System.out.println() just moves to a new line.
  • Pattern problems are the standard way to practice nested loops. The outer loop handles rows, and the inner bound usually depends on i.
⭐ Interview Important: iteration count and time complexity
An outer loop of n iterations with an inner loop of m gives n × m total iterations. With n = m that's O(n²) (5 × 5 = 25), and three nested loops give O(n³).
Correction: the video says "O(n)" for the triple-nested case, but it's O(n³).

Jump Statements: break & continue

break example: primality test

int p = 9;
int i;                              // declared outside so it can be used after the loop (scope)
for (i = 2; i < p; i++) {
    if (p % i == 0) {               // found a divisor
        System.out.println("The number is not prime");
        break;                      // no need to check further divisors
    }
}
if (i == p) System.out.println("The number is prime");   // the loop finished without a break
  • i == p after the loop means no break happened, so no divisor was found. With p = 9 the loop breaks at i = 3. With p = 7 it runs to the end.
  • break lets you exit a loop dynamically, based on something found while it runs, instead of changing the loop's condition.
  • The video mentions a faster version. You only need to check divisors up to √p (i * i <= p). It also skips edge cases: this code prints nothing for p ≤ 1.

continue example: odd numbers

for (int i = 1; i <= 10; i++) {
    if (i % 2 == 0) continue;   // even: skip the print and move to the next i
    System.out.println(i);      // prints 1 3 5 7 9
}

break and continue in nested loops

  • A plain break or continue affects only the innermost loop it's written in. In the star pattern, adding if (j >= 5) break; to the inner loop caps every row at 5 stars. The outer loop still runs all 10 rows, so the triangle "flattens" after row 5.
  • Not covered in the video: a break inside a switch that's inside a loop exits only the switch, not the loop.

Labels: break/continue an Outer Loop

outer:
for (int i = 1; i <= 10; i++) {
    inner:
    for (int j = 1; j <= i; j++) {
        System.out.print("* ");
        if (j >= 5) break outer;     // exits BOTH loops: output stops after the 5th row
    }
    System.out.println();
}
  • Syntax: labelName: before the loop. Then use break labelName; or continue labelName;. This is useful for escaping deeply nested loops.
  • continue outer; skips the rest of the inner loop and the rest of the outer body, and goes to the outer loop's next iteration. Verified: if (y == 2) continue outer; prints 11 21 31.
  • Java also allows standalone labelled code blocks: first: { second: { … break first; } }. break can exit a labelled block. continue can't: continue first; on a block fails with "not a loop label" (not mentioned in the video). These blocks are rarely used, apart from grouping code.
  • Unlike C, Java has no goto. Labelled break and continue are the structured replacement (goto is reserved but unused; see Video 3).
⭐ Quick Revision / Likely Interview Questions
• Three loops in Java? → while, do-while, for (plus for-each for arrays and collections).
• while vs do-while? → Entry-controlled (0+ runs) vs exit-controlled (at least 1 run). do-while suits menus.
• for loop order? → init once, then condition → body → update, repeated. All three parts are optional: for(;;) is infinite.
• Can a for loop have multiple variables? → Yes, comma-separated in init and update. The condition must combine them with && or ||.
• Scope of i in for (int i…)? → Only inside the loop.
• Why use int counters and not byte? → No memory benefit (promotion, 32-bit slots), and a byte counter can wrap around and loop forever.
• Nested loop cost? → n × m iterations: O(n²) for two, O(n³) for three.
• break vs continue? → break exits the loop, continue skips to the next iteration. Both affect only the innermost loop unless labelled.
• How do you exit an outer loop from an inner one? → A labelled break: break outer;.
• Does Java have goto? → No, it's a reserved but unused keyword. Use labelled break and continue instead.

Video 9: Arrays & Intro to Strings

Why Arrays?

Storing 100 students' roll numbers as int rollNo1, int rollNo2, and so on means 100 separate variables and 100 separate memory allocations. An array instead allocates one contiguous block of memory divided into equal cells, all under one name.

⭐ Definition: An array is a fixed-size collection of elements of the same data type, stored in contiguous memory and accessed by index.

Declaring & Creating a 1D Array

int[] rollNumbers;                 // declaration: "rollNumbers will refer to an array of ints"
rollNumbers = new int[3];          // definition: allocate 3 int cells
int[] rollNumbers = new int[3];    // both in one line
int rollNumbers[] = new int[3];    // also legal: C/C++ style, kept for legacy. Java prefers int[]
  • int is the element type, [] marks it as an array, rollNumbers is the name, and 3 is the size.
  • new allocates the array's memory on the heap (heap and objects are covered with OOP). The compiler needs the element type to know each cell's size, e.g. 3 × 32 bits for int.
  • The size is fixed once created (not in the video).

Storing & Reading Elements

rollNumbers[0] = 1001;                  // write to index 0
rollNumbers[1] = 1002;
rollNumbers[2] = 1003;
System.out.println(rollNumbers[2]);     // read: 1003

Not covered in the video: a new array's cells hold default values until you assign them: 0 for int/long/…, 0.0 for float/double, false for boolean, '\u0000' for char, and null for objects such as String.

Loops + .length

int x = 1001;
for (int i = 0; i < rollNumbers.length; i++) {   // don't hard-code 3
    rollNumbers[i] = x++;                        // fill 1001, 1002, 1003
}
for (int i = 0; i < rollNumbers.length; i++) {
    System.out.println(rollNumbers[i]);          // print them
}
  • arr.length gives the number of elements. Use it rather than hard-coding the size, since the size may be unknown or change later.
  • Correction: the video calls length a method. For arrays it's a field, so there are no parentheses: arr.length. For Strings it's a method, str.length(). Mixing these up is a classic interview trap.
  • Valid indexes are 0 to length − 1, so the loop condition is i < arr.length, not <=.

Out-of-Bounds Access

System.out.println(rollNumbers[3]);
// java.lang.ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3
  • An exception is Java's way of signalling at runtime that something went wrong. Exceptions get their own video later.
  • Correction: the exact name is ArrayIndexOutOfBoundsException, not "IndexOutOfBoundException". It is a subclass of IndexOutOfBoundsException.
  • It happens at runtime, not compile time: the compiler doesn't check index values. Unlike C, Java never lets you read past the end into random memory.
  • Not covered in the video: a negative size, new int[-1], throws NegativeArraySizeException.

Array Initializer (values known up front)

int[] rollNumbers = {1001, 1002, 1003};      // size inferred as 3, no 'new' needed
int[][] marks = { {12, 14, 56}, {34, 45, 67}, {45, 67, 78} };

Not covered in the video: the {…} shortcut works only in the declaration statement. arr = {1, 2}; on a later line doesn't compile. Use arr = new int[]{1, 2}; instead.

Multi-Dimensional Arrays

A 2D array is an array of arrays: each element of the outer array is itself an array. Use case: the marks of 3 students (rows) in 3 subjects (columns: Hindi, English, CSc).

int[][] marks = new int[3][3];   // [rows][columns]
marks[0][0] = 50;  marks[0][1] = 30;  marks[0][2] = 90;   // student 1
marks[1][0] = 60;  marks[1][1] = 40;  marks[1][2] = 80;   // student 2
marks[2][0] = 70;  marks[2][1] = 50;  marks[2][2] = 70;   // student 3

Traversing a 2D array (nested loops)

for (int row = 0; row < marks.length; row++) {           // number of rows
    for (int col = 0; col < marks[row].length; col++) {  // length of THIS row
        System.out.print(marks[row][col] + " ");
    }
    System.out.println();                                // new line after each row
}
⭐ Interview Important: marks.length vs marks[row].length
marks.length is the number of rows (the outer array's length). marks[row].length is the number of columns in that row. Using marks.length for columns only works when the array is square, and breaks for jagged arrays.

Jagged Arrays (rows of different lengths)

int[][] marks = new int[3][];   // number of rows required; column size can be left out
marks[0] = new int[1];          // each row created separately
marks[1] = new int[2];
marks[2] = new int[3];
  • Not covered in the video: new int[][3] (column size but no row size) doesn't compile. Only the first dimension is required.
  • Not covered in the video: after new int[3][], each marks[i] is null until you assign a row to it.

3D and Higher Arrays

int[][][] arr = new int[3][3][3];   // an array of arrays of arrays
  • Conceptually it's a cube: 3 stacked 3×3 matrices (rows, columns, depth). Logically it's an outer array whose slots point to arrays, whose slots point to int arrays. arr[0][0] is itself an int array.
  • Java supports any number of dimensions, but in practice 2D is common, 3D is rare, and beyond that almost never.
⭐ Declaration traps (not covered in the video)
• int[] a, b; makes both a and b arrays, but int a[], b; makes only a an array and b a plain int. This is one reason to prefer the int[] style.
• System.out.println(arr) doesn't print the elements. It prints a type code plus a hash, e.g. [I@1b6d3586. Use Arrays.toString(arr) for 1D and Arrays.deepToString(arr) for 2D and beyond.

Intro to Strings

  • Data types are either primitive (byte, short, int, long, float, double, char, boolean) or non-primitive: arrays, String, and objects in general. Strings are covered in depth after OOP.
  • A String is a sequence of characters written in double quotes. A char uses single quotes: 'a'. String has a capital S because it's a class, not a primitive.
  • Everything you've been printing with println("Hello") was already a String. "" (an empty string) and " " (a space) are both valid Strings.
String firstName = "Aditya";
String lastName  = "Tandon";
String fullName  = firstName + " " + lastName;   // + joins strings (concatenation)
System.out.println(fullName);                   // Aditya Tandon
System.out.println(firstName + lastName);       // AdityaTandon (no space is added for you)
⭐ Interview Important: + is evaluated left to right (not covered in the video)
"1" + 2 + 3 gives "123": once a String appears, every later + is concatenation.
1 + 2 + "3" gives "33": 1 + 2 is integer addition first, then the result is concatenated with "3".

Video 10: Arrays in Memory: Random Access, Stack vs Heap, 2D & String Arrays

Random Access

arr[2] goes straight to index 2. The JVM doesn't walk 0 → 1 → 2. This direct jump is called random access, and it takes the same time, O(1), for any index. To see how it works, we first need to know where arrays live in memory.

Primitive vs Non-Primitive Storage

  • Primitive (int x = 4;): the variable directly holds the value. A local primitive lives on the stack.
  • Non-primitive (int[] arr = new int[5];): new creates the array on the heap. The variable arr on the stack is a reference variable. It doesn't hold the array. It holds the array's address, and the video draws it as an arrow.
  • Rule of thumb from the video: anything made with new goes on the heap. Stack and heap get a full video in memory management.
  • Precision (not covered in the video): "primitives live on the stack" is true only for local variables. A primitive that's a field of an object, or an element of an array, lives on the heap along with that object. The ints inside new int[5] are on the heap.

The Address Formula

⭐ Interview Important: Why arrays give O(1) access
address of arr[i] = base address + (element size × i)
• Base address: where the array starts. The reference variable arr stores it.
• Element size: known from the type. It's 4 for int, 8 for long/double.
• i: the index you wrote.
This only works because the memory is contiguous and every element is the same size. It's also why indexes start at 0: index 0 is offset 0.

Precision (not covered in the video): a real Java array object begins with a small header (object metadata plus the length field, about 16 bytes on HotSpot), so element 0 sits a fixed offset after the address the reference holds. The formula is then ref + headerOffset + size × i, still O(1). Java never shows you real addresses. Treat the numbers here as a mental model.

Element typeSize (bytes)
byte1
short, char2
int, float4
long, double8
booleannot fixed by the spec. 1 in boolean arrays on HotSpot/OpenJDK
reference (String, inner arrays, objects)4 as the video says. More precisely 4 with compressed oops (the 64-bit default for heaps under ~32 GB), otherwise 8

Special Case: Size of boolean

  • The official Java spec gives boolean no fixed size. The JVM implementation for each platform decides.
  • In theory 1 bit is enough (0 = false, 1 = true), but HotSpot and OpenJDK use 1 byte per element of a boolean[].
  • Why not 1 bit? Hardware works in bytes, not bits. The video says the CPU always fetches bytes. More precisely, memory is byte-addressable: a byte is the smallest unit that has its own address. Reading one bit would mean loading a byte and then masking it, which is extra work on every access. Java leaves the size open so each JVM can choose what is fastest on its platform.
  • So new boolean[5] at base 100 has elements at 100, 101, 102, … and arr[2] = 100 + 1 × 2 = 102.
  • Not covered in the video: a standalone boolean local variable is usually treated as an int (4 bytes) inside the JVM. If you really need 1 bit per flag, use java.util.BitSet.
⭐ Interview Important: "What is the size of boolean in Java?"
It isn't defined by the spec and depends on the JVM. In practice it's 1 byte in arrays because memory is byte-addressable. A local boolean typically takes an int-sized slot.

Why ArrayIndexOutOfBoundsException Exists

Take arr[100] on an array of size 5. The formula alone would give 100 + 4 × 100 = 500 and read whatever happens to be there, possibly memory that belongs to something else. Java checks the bounds first, and only then applies the formula:

// conceptually, on every array access:
if (index < 0 || index >= arr.length) {
    throw new ArrayIndexOutOfBoundsException(index);
}
// only now: address = base + size * index
  • Correction: the video writes index > length. It must be >=, because arr[length] is already out of bounds (the last valid index is length − 1).
  • This check is what makes Java memory safe compared with C/C++, where reading out of bounds is undefined behaviour. The check happens at runtime, done by the JVM, not by the compiler. The JIT often removes it when it can prove the index is in range, e.g. in for (i = 0; i < arr.length; i++).

2D Arrays in Memory

int[][] arr = new int[3][4]; is read as "an array of size 3, where each element is itself an array of size 4". Java has no true 2D array, only an array of arrays:

  • The outer array (size 3) holds 3 references, each 4 bytes. arr[0], arr[1] and arr[2] are unnamed reference variables that store the base address of their row.
  • Each reference points to a separate int[4] row somewhere else on the heap.
  • Access arr[i][j] applies the formula twice: first to find the row reference, then to find the element inside that row.

Correction: the video's worked example says arr[1] points to base 200, but in its own final drawing row 1 is at 300 (200/300/400 for rows 0/1/2). The diagram uses the final drawing. Either way the method is the same: row lookup, then column lookup.

  • The same idea extends to 3D and beyond: an array of arrays of arrays, with one lookup per dimension.
  • boolean[][]: the outer references are 4 bytes each and the inner elements 1 byte. double[][]: references 4, elements 8.
⭐ Interview Important: Java 2D arrays vs C 2D arrays (not covered in the video)
In C, int a[3][4] is one contiguous block in row-major order: address = base + (i × cols + j) × size, one computation. In Java, each row is a separate heap object, so there are two dereferences, rows can be scattered, rows can have different lengths (jagged), and a row can even be null.

Array of Strings

String[] names = new String[3];
names[0] = "Aditya"; names[1] = "Abhay"; names[2] = "Rohit";
System.out.println(names[1]);   // Abhay
  • Strings have no fixed size, and String is non-primitive, so the array can't hold the strings inline. names is an array of references, each 4 bytes, pointing to String objects elsewhere on the heap. This is the same shape as a 2D array.
  • names[1]: base 400 + 4 × 1 = 404, read 4 bytes to get a reference, then follow it to "Abhay".
  • Correction on what's inside a String: the video says Strings were char arrays "up to JDK 9". It was up to JDK 8. Before that, a String wrapped a char[] (2 bytes per char). JDK 9's Compact Strings (JEP 254) changed this to a byte[] plus an encoding flag: 1 byte per char for Latin-1 text, 2 bytes (UTF-16) otherwise. More on this in the Strings video.

Benefit: Cache Friendliness

  • The CPU doesn't fetch just the one element you asked for. It also pulls in the neighbouring bytes. Because array elements are contiguous, arr[4] is probably already loaded when you read arr[3], and the next access avoids a trip to RAM. The video calls this caching.
  • Correction on the details: the video says the CPU fetches about 8 bytes into its registers. It's really the CPU cache (L1/L2/L3), loaded in cache lines of typically 64 bytes, which is 16 ints at once. Registers are a separate, tiny set of working slots.
  • The formal name is spatial locality. Strictly speaking it comes from contiguity, not from random access itself. Both come from the same contiguous layout.
  • Not covered in the video: for 2D arrays, traverse row by row (arr[i][j] with j in the inner loop). Going column by column jumps between separate row arrays and wastes the cache. It gives the same result but is noticeably slower on large arrays. Linked lists lose this benefit entirely: their nodes are scattered, which is a classic array-vs-linked-list interview point.
⭐ Quick Revision / Likely Interview Questions
• Why is array access O(1)? → Contiguous, same-sized elements: base + size × i.
• Where is int[] arr = new int[5] stored? → The array object is on the heap. The reference arr (if it's a local) is on the stack and holds the array's address.
• Primitive vs reference variable? → A primitive holds the value. A reference holds an address pointing to an object.
• Size of boolean? → Not defined by the spec. 1 byte in arrays on HotSpot, because memory is byte-addressable.
• Size of a reference? → 4 bytes with compressed oops (the default), 8 without.
• Why check bounds before accessing? → To avoid reading unrelated memory. Throws ArrayIndexOutOfBoundsException if index < 0 || index >= length.
• How is arr[i][j] found? → The formula twice: find the row reference in the outer array, then the element in that row.
• Is a Java 2D array contiguous? → No. It's an array of references to separate row arrays (unlike C).
• What does a String[] hold? → References to String objects, not the characters.
• String internals before and after JDK 9? → char[] up to 8, then byte[] + coder (Compact Strings).
• Why are arrays cache-friendly? → Spatial locality: 64-byte cache lines bring in neighbouring elements.

Why Functions?

If you need "add two numbers and print the sum" in five places, copy-pasting the same lines five times is repeated code. A function is a named block of code written once that you call whenever you need it. That's code reusability.

  • Until OOP these are called functions. After OOP they're called methods. In Java every function lives inside a class, so strictly speaking they're all methods.
  • Same idea as maths: f(x) takes an input, does some processing and gives an output.

Syntax

public class Demo {
    public static void main(String[] args) {
        int i = 4, j = 5;
        int result = sum(i, j);          // calling the function; i, j are ARGUMENTS
        System.out.println(result);      // 9
        int c = sum(10, 9);              // literals work as arguments too: 19
    }

    //  return type  name   parameters
    static int       sum   (int a, int b) {
        int result = a + b;
        return result;                   // sends the output back to the caller
    }
}
  • Where: define functions outside main, but inside the class. Java doesn't allow a function inside another function.
  • static: treat it as required for now. It's explained with OOP. Briefly: main is static, so it can directly call only other static methods.
  • Return type: the data type of the value the function returns (int here). void means it returns nothing.
  • Parameters: int a, int b, the inputs, each declared with a type and a name.
  • return: ends the function and hands the value back. int result = sum(i, j); receives it with the assignment operator.
⭐ Interview Important: Parameters vs Arguments
• Parameters (formal parameters) are the variables in the function definition, int a, int b. They're placeholders that say "give me any two ints".
• Arguments (actual parameters) are the actual values passed at the call, sum(i, j) or sum(10, 9).
At the call, the arguments are copied into the parameters: a = 4, b = 5. The names don't need to match.
⭐ Interview Important: Java is always pass-by-value (not covered in the video)
The parameter gets a copy of the argument. Changing a inside sum never changes i in main. For an array or object argument, the value copied is the reference (see Video 10). So the function can modify the array's contents, but reassigning the parameter (arr = new int[3]) doesn't affect the caller's variable.

main Is Also a Function

public static void main(String[] args) reads like any other function: static, return type void, name main, one parameter args (a String array). Because it's void, a trailing return; is optional here too.

  • The JVM calls main. It's the entry point of every Java program, and execution goes line by line from there.
  • A function that is defined but never called (directly or indirectly from main) never runs. An empty main prints nothing, however many functions the class defines.
  • When a call is reached, control jumps into the function, runs it, then returns to the caller and continues from the next line.
  • Not covered in the video: args holds the command-line arguments, e.g. java Demo hi 5 gives args = {"hi", "5"}. public is needed so the JVM can call main from outside the class, and static so it can call it without creating an object.

Function Overloading

Functions doing almost the same job can share one name if their parameter lists differ. The compiler picks the right one from the arguments at the call.

static int sum(int a, int b)           { return a + b; }
static int sum(int a, int b, int c)    { return a + b + c; }      // different NUMBER of params
static int sum(double a, double b)     { return (int) (a + b); }  // different TYPES of params

static void greet(String name, int age) { System.out.println("Hi " + name + ". Your age is " + age); }
static void greet(int age, String name) { System.out.println("Hi " + name + ". Your age is " + age); } // different ORDER

sum(5, 6);            // → sum(int, int)          11
sum(3, 5, 6);         // → sum(int, int, int)     14
greet("Aditya", 28);  // → greet(String, int)
greet(28, "Rohit");   // → greet(int, String)

Without overloading you'd need sum2, sum3 and so on, or ugly workarounds like sum(3, 4) + 5.

⭐ Interview Important: Rules of overloading
Overloaded functions must differ in the parameter list:
① the number of parameters, ② the types of parameters, or ③ the order of parameter types.
Return type alone is NOT enough. void fun() plus int fun() gives "Duplicate method fun()". Why: the return value can be ignored, so for a bare call fun(); the compiler couldn't tell which one you meant.
Fix: rename it, or change the parameters.
  • Not covered in the video: the name plus the parameter types, in order, is the method signature. The return type and parameter names aren't part of it. sum(int x, int y) is a duplicate of sum(int a, int b).
  • "Order" only helps when the types differ. (int a, int b) vs (int b, int a) is the same signature.
  • Overloading is resolved at compile time, so it's also called compile-time (static) polymorphism. Contrast it with overriding in OOP later.
  • Not covered in the video: if there's no exact match, Java tries widening. With only sum(double, double), sum(2, 3) still works (int → double). If two candidates fit equally well, the call is an ambiguous compile error.

Scope of a Variable

  • Local scope: a variable declared inside { } (a function, if, for, while or any block) is visible only inside that block. When the block ends, the variable is destroyed.
  • So x and y from main can't be used in fun(): "x cannot be resolved to a variable". Either pass them as arguments (fun(x, y) with static void fun(int x, int y)), or declare new ones inside fun. Those would be completely separate variables that happen to share a name.
  • A variable declared inside an if block can't be used after the block. Declaring a new j after the block is fine because the old one no longer exists.
public class Demo4 {
    static String name = "Aditya";          // class-level: visible in every method of the class

    public static void main(String[] args) {
        int x = 4;                           // local to main
        if (x == 4) {
            int j = 7;                       // local to this if block
            System.out.println(j);           // ✔ 7
        }
        // System.out.println(j);           // ✘ j cannot be resolved
        System.out.println(name);            // ✔
        fun();
    }
    static void fun() {
        // System.out.println(x);           // ✘ x belongs to main
        System.out.println(name);            // ✔
    }
}
  • The video calls name a global variable. Correction: Java has no true global variables. This is a static field (class variable), and it lives as long as the class is loaded, not "as long as the file". It needs static here because main is static ("Cannot make a static reference to the non-static field").
  • Not covered in the video: unlike C, Java doesn't allow a local variable to be redeclared in a nested block while the outer one is still in scope. int j = 1; if (…) { int j = 2; } is a compile error. A local variable can shadow a field with the same name. Use ClassName.field (or this.field for instance fields) to reach the field.
  • Not covered in the video: local variables get no default value. Using one before assigning it is the compile error "variable might not have been initialized". Fields do get defaults.

Recursion

⭐ Definition: Recursion is when a function calls itself, each time on a smaller input. Every recursive function needs:
① a base case, where recursion stops and control starts returning. Without it the calls never end.
② a recursive call that moves toward the base case (n − 1, n − 2, …).

Example: print 1 to n recursively

static void printNum(int n) {
    if (n == 0) return;          // base case: stop
    printNum(n - 1);             // recursive call on a smaller problem
    System.out.println(n);       // runs on the way BACK
}
printNum(5);                     // 1 2 3 4 5
  • Going down: printNum(5) → 4 → 3 → 2 → 1 → 0. At 0 the base case returns immediately.
  • Coming back up: each call resumes after its recursive call and prints its own n. So 1 prints first, then 2, 3, 4, 5. It's exactly the chaining above, just with the same function each time. The video's analogy: walk down the stairs to the floor (the base case), then print while climbing back up.
  • Swapping the two lines (print before the recursive call) prints 5 4 3 2 1. That's a good first exercise.
  • Iteratively, a simple for loop does this. Recursion pays off for problems that are naturally defined in terms of smaller versions of themselves: trees, divide and conquer, backtracking, DSA problems.
⭐ Interview Important: No base case → StackOverflowError
The video says recursion without a base case runs forever. Correction: an infinite loop runs forever, but infinite recursion crashes. Every call takes a new frame on the call stack, and the stack is finite, so the JVM throws java.lang.StackOverflowError (an Error, not an Exception). Even with a correct base case, very deep recursion (e.g. n = 100000) can overflow the stack. That's one reason iteration is sometimes preferred.

Example: n-th Fibonacci (two recursive calls)

Series: 1, 1, 2, 3, 5, 8, 13, … where each term is the sum of the previous two. Mathematically fib(n) = fib(n−1) + fib(n−2), and the code is a direct translation of that:

static int fib(int n) {
    if (n == 0 || n == 1) return 1;   // base cases (video's indexing: fib(0)=1, fib(1)=1)
    int x = fib(n - 1);
    int y = fib(n - 2);
    return x + y;
}
fib(4);   // 5      fib(5);   // 8
  • Correction: the video says the base case is "if n is 0 and n is 1". It must be OR (||), because n can't be both at once. With && the base case never triggers, and you get a StackOverflowError.
  • Note: the standard definition is fib(0) = 0, fib(1) = 1 (0, 1, 1, 2, 3, 5, …). The video's version is shifted by one index. Clarify which one the interviewer wants.
  • Recursive leap of faith (the video's key tip): don't trace every level in your head. Assume fib(n−1) and fib(n−2) already return correct answers, and write only how to combine them, plus the base case.
⭐ Interview Important: Why naive recursive Fibonacci is slow (not covered in the video)
The same subproblems are solved again and again. fib(2) is computed twice for n = 4, and the repetition explodes as n grows. Time is about O(2ⁿ) (more precisely about 1.6ⁿ), and space is O(n) for the stack depth. Fix it with memoization: cache each fib(k) in an array the first time it's computed, which gives O(n). Or use an iterative loop with two variables, which is O(n) time and O(1) space. This is the classic entry point to dynamic programming.

Practice suggested in the video: print 1 to n, print n to 1, then the Fibonacci dry run on paper.

The Problem with the "Traditional" Approach

String name = "Aditya";  int age = 28;  int rollNo = 1001;  String college = "IIT Guwahati";
String name2 = "Rohit";  int age2 = 28; int rollNo2 = 102;  String college2 = "IIT Guwahati";
static void print(String name, int age, int rollNo, String college) { … }
  1. Many independent variables for one student. Nothing in the code says these 4 belong together. Only we know that.
  2. Passing a student to a function means passing all 4 values, and forgetting one breaks it. The function has no idea it's dealing with "a student".
  3. Every new student needs a new set of variables: name2, age3, and so on.
  4. No authority over the data. Nobody "owns" these variables, so any code anywhere can change them. This sets up encapsulation later.

Object-Oriented Programming (OOP)

  • OOP is a programming paradigm, a way of thinking about and structuring code. It's not a language feature bolted on. Other paradigms exist, e.g. procedural (C) and functional (Haskell). Java is an OOP language.
  • Core idea: we write code to solve real-world problems, so we mimic the real world in code. The real world is made of objects (living or non-living entities), so the program should be made of objects too.
  • Instead of thinking in scattered variables and functions, think in terms of objects: one block that holds everything about one entity.

Another example is an Animal. Its characteristics are type, number of legs, and wild vs domestic. Its behaviours are makeSound(), eat() and run(). Behaviour is as much a part of the object as its data, so both go inside the class.

⭐ Model only what the problem needs
A real human plays many roles: a student at college, a son or daughter at home, an employee at the office. Each role has many more characteristics than we'd ever code, such as grades, subjects, employee ID or salary. We don't model the whole hierarchy. For a college attendance portal, we model only the student part, and only the fields the app needs. This is the essence of abstraction (formally covered later): keep the relevant details, hide or ignore the rest.
  • A digital object can also have behaviours its real-world counterpart doesn't. A real student can't "print itself", but a Student object can have print(). Add whatever makes the code easier to use.
  • Objects needn't be physical. BankAccount (account number, IFSC, branch) and Location (latitude, longitude) aren't physical things, but each bundles several values, so each gets a class. Rule: anything too complex for a single primitive variable becomes a class.

Class = Blueprint, Object = Instance

"Student" is an abstract idea: every student has a name, age, roll number and college. "Arun" and "Varun" are specific students. Java mirrors this:

  • Class: the abstract idea, the blueprint of an object. It describes what an object will look like. It is not the data itself. Declaring a class creates no student in memory.
  • Object: a concrete instance of the class, with its own actual values, created in memory at runtime. One class can have any number of objects.
class Student {                       // class name → PascalCase
    String name;                      // characteristics → fields
    int age;
    int rollNo;
    String college;

    void markAttendance() {           // behaviour → method
        System.out.println("Attendance marked by " + name);   // uses this object's own name
    }
    void print() {                    // no parameters needed: the fields are already accessible
        System.out.println(name + ", " + age + ", " + rollNo + ", " + college);
    }
}

User-defined data types

  • Data types are primitive (int, float, char, boolean, …: one value each) or non-primitive (arrays, String, and every object: a container of several things).
  • Some non-primitive types come built into Java (String, arrays, …). The ones we create with class are user-defined data types. Student is now a type, just like int: Student s1; reads like int x;.

Creating Objects: new

Student s1;                  // declaration: a reference variable of type Student (no object yet)
s1 = new Student();          // new allocates the object on the heap; its address goes into s1
Student s2 = new Student();  // both in one line

s1.name = "Aditya";  s1.age = 28;  s1.rollNo = 1001;  s1.college = "IIT Guwahati";   // write with the dot operator
s2.name = "Rohit";   s2.age = 28;  s2.rollNo = 102;   s2.college = "IIT Guwahati";

System.out.println(s1.name);     // read: Aditya

s2.markAttendance();             // Attendance marked by Rohit
s1.print();  s2.print();
  • new Student() tells the JVM to allocate a chunk of heap memory big enough for a Student object. (Student() with parentheses is the constructor call, covered next lecture.)
  • The starting address of that chunk is assigned to s1. s1 lives on the stack and is a reference variable: a special variable that stores a reference (address) to an object.
  • The dot operator follows the reference to the object, then picks a field or method. Reading and writing work just like a normal variable.
  • Now print(Student s) can take one argument instead of four. Better still, the method lives inside the class, so each student prints itself and needs no parameters.
⭐ Interview Important: "Is s1 the object?" No.
s1 is a reference variable (on the stack, if it's a local). The object is the unnamed block on the heap that new created. s1 only holds its reference. People casually say "object s1", but in an interview make the distinction.
  • Correction: the video's memory drawing puts markAttendance() inside each object. In reality method code isn't copied per object. It's stored once per class (in the method area / Metaspace), and every object carries a pointer to its class. Objects hold only their fields plus a small header. When s1.markAttendance() runs, the method knows which object it's working on (that's this, later), so name means s1's name.
  • Not covered in the video: fields get default values (null for String and other references, 0 for int, false for boolean), so new Student() starts as null, 0, 0, null. Local variables get no default.
  • Not covered in the video: Student s1; alone creates no object. Using an uninitialised local is a compile error. Using a reference that's null (s1 = null; s1.name) compiles but throws NullPointerException at runtime.
⭐ Interview Important: Assigning a reference copies the address, not the object (not covered in the video)
Student s3 = s1; creates no new object. s3 and s1 now point to the same object, so s3.name = "X" also changes s1.name. s1 == s3 is true, because == on references compares addresses, not contents. Only new creates a new object.

Compile Time vs Runtime, Static vs Dynamic Allocation

  • Compile time is when javac checks and translates the code. Syntax and type errors show up here, as the red squiggle in the IDE. Runtime is when the program actually executes. Exceptions such as ArrayIndexOutOfBounds or NullPointerException happen here.
  • new allocates memory at runtime, so it's called dynamic memory allocation. Nothing is on the heap just because you wrote the code. It happens when that line executes.
  • The video labels int x = 4; as compile-time (static) allocation. Precision: a local's slot still comes into existence at runtime, when the method's stack frame is pushed. What's fixed at compile time is its size and layout (the compiler already knows the frame needs 4 bytes for x). With new, the amount and number of objects are decided at runtime, e.g. new int[n] or objects created in a loop.

Instance Variables vs Local Variables

  • Instance variables are the fields declared in a class, representing an object's data or characteristics. Each object gets its own copy, stored inside the object on the heap.
  • Instance methods are methods defined in a class, representing behaviour. Often just called "methods".
  • Local variables are declared inside a method or block, e.g. int x = 4; in main. They live on the stack and die when the method or block ends.

The video's reason is optimisation: locals are short-lived, so Java skips giving them defaults. An uninitialised read is almost always a bug, so it's made a compile error. For fields, the compiler can't know in what order methods will run, so the JVM zeroes the object's memory when allocating it, which gives 0, false and null.

Constructors

Assigning every field one by one after creating the object (s1.name = …; s1.age = …;) is tedious and error-prone: forget one and it silently stays at its default. A constructor initialises the object at the moment it's created.

⭐ Rules of a constructor
① Its name is the same as the class.
② It has no return type, not even void.
③ It runs automatically when an object is created. More precisely, new Student() is the call: the Student() after new invokes the constructor.
④ It's used to initialise the object.
⑤ It can be overloaded, like any method.
class Student {
    String name; int age; int rollNo; String college;

    Student() {                       // hard-coded initial values
        name = "Aditya"; age = 28; rollNo = 1001; college = "IIT Guwahati";
    }
}
Student s1 = new Student();           // s1.name → "Aditya", not null

What Student s1 = new Student(); really does

  1. new allocates memory for the object on the heap, at runtime.
  2. All fields are set to their default values (null, 0, …).
  3. The constructor Student() runs and overwrites them with the values it sets.
  4. The object's reference (its address) is returned and stored in s1 on the stack.
⭐ Interview trap: adding void to a constructor (not covered in the video)
void Student() { … } compiles, but it's now an ordinary method that happens to share the class name. It's not a constructor. new Student() then uses the default constructor, and your initialisation silently never runs.

Default Constructor

  • Every class must have a constructor. If you write none, the compiler adds a default constructor: no parameters and an empty body (Student() { }). That's why new Student() worked in earlier lectures, and why fields came out as null and 0.
  • ⭐ The compiler adds it only if you write no constructor at all. As soon as you write any constructor, parameterized or not, Java stops adding one. With only Student(String n, …) defined, new Student() is the compile error "The constructor Student() is undefined". The fix is to write a no-arg constructor yourself, which is overloading.
  • Strictly speaking (not covered in the video), a constructor you write with no parameters is called a no-arg constructor. "Default constructor" means the one the compiler generates. It isn't truly empty: its first action is super();, which calls the parent class's constructor (inheritance, later).

Parameterized Constructor

Hard-coding "Aditya" in the constructor gives every object the same values. A parameterized constructor takes the values at creation time, and it makes them mandatory: you can't create the object without supplying them.

class Student {
    String name; int age; int rollNo; String college;

    Student() { }                                          // no-arg (overload)
    Student(String n, int a, int rn, String c) {           // parameterized
        name = n; age = a; rollNo = rn; college = c;
    }
}
Student s1 = new Student("Rohit", 28, 102, "IIT Guwahati");  // values passed as arguments
Student s2 = new Student();                                  // allowed only because the no-arg one exists

Correction: the video's whiteboard declares the college parameter as int c. It must be String c, as in the video's actual code.

The this Keyword

this is a reference to the current object, the one the constructor is initialising or the method was called on. Inside a method called as s1.markAttendance(), this points to the same object as s1.

Use 1: telling a field apart from a parameter with the same name

Student(String name, int age, int rollNo, String college) {
    name = name;              // ✘ assigns the parameter to itself: "The assignment to variable name has no effect"
    this.name = name;         // ✔ field = parameter
    this.age = age;
    this.rollNo = rollNo;
    this.college = college;
}
  • When a parameter or local has the same name as a field, the plain name means the parameter. It shadows the field. this.name means the field of the current object.
  • If the names differ (name = n;), this is optional. Still, same names plus this.x = x is the standard Java convention, because it's the most readable.

Use 2: calling another constructor, this(…)

This is constructor chaining. One constructor delegates to another in the same class, so the assignment logic is written only once.

class Student {
    String name; int age; int rollNo; String college;

    Student()                                   { this("Unknown");                          System.out.println("1st"); }
    Student(String name)                        { this(name, 0);                            System.out.println("2nd"); }
    Student(String name, int age)               { this(name, age, 0);                       System.out.println("3rd"); }
    Student(String name, int age, int rollNo)   { this(name, age, rollNo, "Unknown");       System.out.println("4th"); }
    Student(String name, int age, int rollNo, String college) {      // the only place fields are assigned
        this.name = name; this.age = age; this.rollNo = rollNo; this.college = college;
        System.out.println("5th");
    }
}
Student s1 = new Student();   // prints 5th 4th 3rd 2nd 1st; fields: Unknown 0 0 Unknown
  • Two styles of chaining: every constructor calls the full one directly (this(name, 0, 0, "Unknown")), or each calls the next bigger one (the diagram). Both give the same result.
  • The video passes "Unknown" instead of null for missing Strings, to avoid NullPointerException later.
⭐ Rules of this(…)
• It must be the first statement in the constructor. Anything above it, even a println, is a compile error.
• It can be used only inside a constructor, not in a normal method.
• Not covered in the video: this(…) and super(…) can't both appear in one constructor, since both must be first. Constructors calling each other in a cycle is the compile error "recursive constructor invocation".
• Not covered in the video: this can't be used in a static context (e.g. directly in main), because no current object exists there.

How Big Is a Reference?

  • A reference variable (e.g. s1 in Student s1 = new Student();) is 4 bytes or 8 bytes, depending on the JVM.
  • More precisely: a 64-bit HotSpot JVM uses compressed references ("compressed oops") by default for heaps under ~32 GB, and those are 4 bytes. Without compression (very large heaps, or the flag turned off) they're 8 bytes. A 32-bit JVM always uses 4. The usual answer is 4.

Correction: the video relates the class pointer to the this keyword, as if it were a reference to the object itself. It isn't. It points to the object's class (the Student class metadata in Metaspace). this isn't stored in the object at all. It's simply the reference the method was called through.

  • Correction: in the Person example the video adds 12 + 1 + 3 and says 18 bytes. The correct total is 16, which is the whole point of padding: the result must be a multiple of 8.
  • Why pad to multiples of 8? The video says it's because the CPU fetches 8-byte chunks. More precisely, HotSpot aligns every object to 8 bytes (-XX:ObjectAlignmentInBytes). Aligned addresses make field access efficient, and alignment is also what makes compressed oops work. Since every object starts at a multiple of 8, a 32-bit reference can store address ÷ 8, and that's how 4 bytes can address up to 32 GB.
  • Not covered in the video: this is the shallow size, i.e. the object alone. The objects it references (the two Strings) take extra memory and aren't counted. The JVM may also reorder fields to minimise padding. An array header has an extra 4-byte length (12 + 4 = 16 bytes before the elements). To see the real layout, use JOL (Java Object Layout): ClassLayout.parseClass(Student.class).toPrintable().
⭐ Formula: object size = header (mark word 8 + class pointer 4) + sum of the field sizes, rounded up to a multiple of 8. Even an object with no fields takes 16 bytes (12 rounded up to 16).

Call by Value vs Call by Reference

Experiment 1: primitives, where the change is lost

static void add10(int x, int y) { x = x + 10; y = y + 10; }

int x = 4, y = 5;
System.out.println(x + " " + y);   // 4 5
add10(x, y);
System.out.println(x + " " + y);   // 4 5   ← unchanged!

Experiment 2: an object, where the change is visible

class Random {
    int x, y;
    Random(int x, int y) { this.x = x; this.y = y; }
}
static void add10(Random r) { r.x = r.x + 10; r.y = r.y + 10; }

Random r1 = new Random(4, 5);
System.out.println(r1.x + " " + r1.y);   // 4 5
add10(r1);
System.out.println(r1.x + " " + r1.y);   // 14 15   ← changed!
⭐ Interview Important: "Is Java call by value or call by reference?"
Java is strictly call (pass) by value, always, for primitives and objects alike. There is no call by reference in Java (C++ has it with int&).
With objects, the value that gets copied is the reference. So the method can modify the object's contents, which feels like call by reference. A common fresher mistake is to say "by value for primitives, by reference for objects". That's wrong.
⭐ The proof: reassigning a parameter doesn't affect the caller (not covered in the video)
static void reset(Random r) { r = new Random(0, 0); }, then reset(r1);, then r1.x is still 4. The method only rebinds its own copy r. Likewise, a swap(Random a, Random b) method can never swap the caller's variables. With true call by reference, both of these would affect the caller.
  • Parameters and return types can be non-primitive: static Random add10(Random r) { …; return r; } is valid.
  • Parameter reference variables are local variables: r disappears when add10 returns. The object survives because r1 still refers to it. An object that no reference can reach is eligible for garbage collection (covered later).

Copying Objects

Random(Random r) { this.x = r.x; this.y = r.y; }   // copy constructor

Random r1 = new Random(4, 5);
Random r2 = new Random(r1);   // NEW object with the same values → independent
Random r3 = r1;               // NO new object: r3 and r1 point to the SAME object

r3.x = 14;
System.out.println(r1.x);     // 14  (same object)
System.out.println(r2.x);     // 4   (separate object)
  • new appears ⇒ a new object is allocated. No new ⇒ only the reference is copied.
  • After r3 = r1, r1 == r3 is true (same address), but r1 == r2 is false, even though the field values match.
⭐ Correction: what "shallow copy" and "deep copy" really mean
The video calls r3 = r1 a "shallow copy" and new Random(r1) a "deep copy". The standard definitions are different:
• r3 = r1 is just a reference copy (aliasing). No object is copied at all.
• A shallow copy creates a new object and copies each field as is. Primitive fields are duplicated, but reference fields still point to the same inner objects.
• A deep copy creates a new object and recursively copies the objects its fields refer to, so nothing is shared.
Random has only primitive fields, so its copy constructor is shallow and deep at the same time. The difference only shows up with reference fields.
class Student {
    String name; int[] marks;
    Student(Student s, boolean deep) {
        this.name  = s.name;                                    // Strings are immutable → safe to share
        this.marks = deep ? s.marks.clone() : s.marks;          // deep: new array · shallow: same array
    }
}
// shallow: copy.marks[0] = 99 also changes original.marks[0]
// deep:    copy.marks[0] = 99 leaves the original untouched

The Problem static Solves

An app for one college: every Student object has college = "IIT Guwahati". With a normal field, 1,000 students means 1,000 identical copies, and the value never differs. That wastes memory (4 bytes of reference per object) and is error-prone. The college belongs to the class as a whole, not to each object.

Static Variables (Class Variables)

class Student {
    String name; int age; int rollNo;     // instance variables: one copy PER OBJECT
    static String college;                // class variable: ONE copy, shared by all objects
}

Student.college = "IIT Guwahati";         // preferred: ClassName.staticVar
Student s1 = new Student(), s2 = new Student(), s3 = new Student();
s3.college = "IIT Kharagpur";             // legal (with a warning): changes it for EVERYONE
System.out.println(s1.college);           // IIT Kharagpur
  • Access it with ClassName.var, which is the recommended way. s1.college also compiles, but gives the warning "static field should be accessed in a static way".
  • Instance variable means one per object. Class (static) variable means one per class.
  • Correction on "static variables aren't stored on the heap": class metadata (method code, etc.) lives in Metaspace, which isn't the heap. But since Java 8 the static fields' values are stored on the heap, inside the class's java.lang.Class object. (Before Java 8 they were in PermGen.) The model that matters is the same: one shared copy, not per object.
  • Pitfall: assigning a static field inside a constructor (this.college = college compiles, with a warning) overwrites it for every existing object each time a new object is made.

Static Methods

class Student {
    static void markAttendance() { … }
}
Student.markAttendance();     // call with the class name. No object needed.
s1.markAttendance();          // also compiles (with a warning). It's the same shared method.
⭐ Rules for static methods
① A static method can directly call only other static methods.
② It can directly access only static variables.
③ It has no this (and no super).
Why: a static method can run without any object existing (Student.markAttendance()). If it used name or called the instance method print(), which object's name would it mean? There's no current object, so there's no this.
  • Precision: the rule is about direct access, without an object. A static method can use instance members through an explicit reference: static void f() { Student s = new Student(); s.print(); s.name = "X"; } is fine. (This is exactly what main does all the time.)
  • The reverse is always fine: instance methods can use static members.
  • Methods, both static and instance, are never stored inside objects. Objects hold only their instance fields.
  • Not covered in the video: static methods can't be overridden. A subclass method with the same signature hides it instead (covered with inheritance). Trap: calling a static method through a null reference (Student s = null; s.markAttendance();) does not throw an NPE, because the compiler uses only the reference's type.

Static Block

class Student {
    static String college;
    static int grade;
    static {                         // runs ONCE, when the class is initialised, before any object
        college = "IIT Guwahati";
        grade = 8;
    }
}
  • A constructor initialises instance variables. A static block initialises static variables. Simple values can also be assigned directly: static String college = "IIT Guwahati";.
  • The static block runs once per class, before any object and before any constructor.
  • Precision: it runs when the class is initialised. That happens on first use (first new, first static method call, or first static field access), not necessarily at program start. Several static blocks run in textual order.

The final Keyword

final on a variable makes it a constant: it can be assigned only once, and never changed after that.

class Random {
    final double PI = 3.14;
}
Random r1 = new Random();
System.out.println(r1.PI);   // 3.14
r1.PI = 3.16;                // ✘ "The final field Random.PI cannot be assigned"
  • Naming convention for constants: ALL CAPS, with words separated by underscores: PI, PI_VALUE, MAX_SIZE.
  • Where a final field can get its one value: at the declaration, or in the constructor (final double PI; plus this.PI = 3.14; in Random()). A final field that's never assigned is the compile error "blank final field may not have been initialized". If there are several constructors, every one must assign it.
  • Final locals: final int x; x = 4; is allowed, but a second x = 5; gives "The final local variable x may already have been assigned".

Correction: the video first says a final can't be declared on one line and assigned on the next, then shows that it can, and calls it a Java "optimisation". It isn't an optimisation or a special exception. The actual rule is simply "assigned exactly once" (definite assignment). A final left blank at declaration is legal as long as it's assigned exactly once before use: in the constructor for fields, or later in the method for locals.

⭐ Interview trap: a final reference ≠ an immutable object (not covered in the video)
final int[] arr = {1, 2, 3}; means arr[0] = 99; is ✔ allowed, while arr = new int[5]; is ✘ an error.
final freezes the variable, i.e. which object it points to, not the object's contents. The same goes for final Student s: s.name = "X" works, but s = new Student() doesn't.

  • final means it can't change. static means one shared copy, so a static final is the same for every object and never changes. That's the standard way to declare constants, e.g. Math.PI and Integer.MAX_VALUE.

Why Is main Static?

⭐ Interview Important
The JVM must call main to start the program, but no object exists yet. If main were an instance method, the JVM would first have to create an object (new Demo4().main(…)). Which constructor would it use, and with what arguments? Making main static lets the JVM call Demo4.main(args) directly on the class, without creating any object.
Knock-on effect: because main is static, the other methods in the Demo class that main calls directly must also be static. Otherwise you get "Cannot make a static reference to the non-static method". That explains the rule from Video 11.
  • Not covered in the video: public is required so the JVM, which is outside the class, can call it, and void because nothing is returned to the JVM (use System.exit(code) for an exit status).
  • Not covered in the video: newer Java relaxes this. JDK 25 finalised "compact source files and instance main methods", which allow a plain void main() { … } for simple programs. Interviews still expect the classic public static void main(String[] args).

Video 16: OOP Pillars I: Encapsulation (Access Modifiers, Getters/Setters, Packages) & Inheritance (Types, Diamond Problem, super)

The 4 pillars of OOP are Encapsulation, Inheritance, Abstraction and Polymorphism. Each one mimics a property of real-world objects. This video covers the first two.

Encapsulation

Think of a medicine capsule: different ingredients sealed together inside one wrapper. Encapsulation makes two demands:

⭐ Definition: Encapsulation
① Data and behaviour are bundled together inside one unit, the class/object. Fields hold the data and methods hold the behaviour. We've been doing this part all along.
② No unrestricted access to the data. Hide the fields (private) and allow access only through controlled public methods, where validation can happen. This is often called data hiding.

Why ② matters: BankAccount. If balance is a plain field, anyone can write ba.balance = 100000;. In real life you can't set your own balance. It changes only through deposit and withdraw, and the bank validates both (real currency? enough funds?). The code should mimic that.

class BankAccount {
    private double balance;                  // hidden: ba.balance won't compile outside this class

    public void deposit(double amount) {
        if (amount <= 0) throw new IllegalArgumentException("Invalid amount");   // validation lives here
        balance += amount;
    }
    public void withdraw(double amount) {
        if (amount > balance) throw new IllegalArgumentException("Insufficient balance");
        balance -= amount;
    }
    public double getBalance() { return balance; }  // read-only view. There's deliberately NO setBalance()
}

BankAccount ba = new BankAccount();
ba.deposit(500);  ba.withdraw(300);
System.out.println(ba.getBalance());   // 200.0
// ba.balance = 100000;                // ✘ "The field BankAccount.balance is not visible"

Correction: the video's comment writes the withdraw check as "amount ≥ balance" and then corrects itself. The valid condition is amount <= balance, so you reject when amount > balance.

Getters and setters

class Student {
    private String name; private int age; private int rollNo; private String college;

    public String getName()              { return name; }
    public void   setName(String name)   { this.name = name; }
    public String getCollege()           { return college; }
    public void   setCollege(String college) {
        // validation: the college must be real (e.g. look it up via an API) before accepting it
        this.college = college;
    }
}
  • "If setName lets anyone set the name anyway, why not just make it public?" Because the method is a checkpoint: you can add rules at any time (age ≤ 120, roll number within range, the name must include a surname) without changing any calling code.
  • You choose what to expose: a getter only gives read-only access (like balance). Neither getter nor setter means fully internal.
  • Naming convention: getX() / setX(value). For a boolean, isX().

  • With print() at default access, college.Teacher (same package) can call it without any import, but Demo2 (outside) gets "The method print() is not visible" until it's made public. The class must also be public to be used outside its package.
  • Importing college.Student and school.Student together is a conflict: "The import school.Student collides with another import statement". Import one and use the fully qualified name for the other.
  • Built-in packages: java.lang (String, Math, System: imported automatically), java.util (ArrayList and the other collections, Scanner), java.io (input/output). For example, import java.util.ArrayList; or import java.util.*;.
  • Real projects use hierarchical, reverse-domain names: com.company.project.module. Folders nest the same way.

Correction on how imports work: the video says the compiler "loads ArrayList.class into memory" because of the import. In fact an import is only a compile-time naming shortcut: it lets you write ArrayList instead of java.util.ArrayList. It copies no code and loads nothing. The JVM loads a class at runtime, the first time it's actually used. So import java.util.* costs nothing at runtime. Also, * does not import sub-packages.

Inheritance

Real-world objects relate to each other by an IS-A relationship: a Car is a Vehicle, a Bike is a Vehicle, an EngineeringStudent is a Student. The reverse isn't true: not every Vehicle is a Car. Every vehicle can start(), so write that once in Vehicle and let every kind of vehicle inherit it.

class Vehicle {
    void start() { System.out.println("Vehicle starting"); }
}
class Car extends Vehicle {                 // extends = inherits from
    void setGear() { System.out.println("Gear set"); }   // Car-specific: not every vehicle has gears
}
Car c = new Car();
c.start();     // inherited from Vehicle
c.setGear();   // its own
  • Terms: parent / superclass / base class and child / subclass / derived class.
  • A child object can call its own methods plus the parent's non-private ones. A parent object can't call child-only methods: new Student().attendLab() gives "The method attendLab() is undefined for the type Student".
  • private members aren't accessible in the child. Make the parent method private and even the child can't call it. protected, public and default (in the same package) work. Constructors aren't inherited.
  • If the child defines its own start() with the same signature, the child's version is used. The video calls this "shadowing". The correct term for methods is method overriding, covered with polymorphism. "Shadowing/hiding" applies to fields with the same name.
  • Benefits: ① code reusability, with no duplicate start() in Car, Bike, Truck and so on. ② It enables polymorphism (next pillar).
  • Not covered in the video: every class implicitly extends java.lang.Object, the root of all classes. That's where toString(), equals() and hashCode() come from.

Types of Inheritance

class Student              { public void markAttendance() { … } }
class EngineeringStudent    extends Student            { void attendLab() { … } }     // single
class CSEEngineeringStudent extends EngineeringStudent { void attendCSELab() { … } }  // multilevel: has all 3 methods
class MedicalStudent        extends Student            { void attendLab() { … } }     // hierarchical: 2 children of Student

In multilevel inheritance, the bottom class gets every non-private member up the chain. Not covered in the video: hybrid inheritance is a mix of these types. Java allows it only when it doesn't involve multiple inheritance of classes.

Why not multiple inheritance? The Diamond Problem

  • Correction: the video says the problem arises "at runtime". Java prevents it at compile time: extends simply accepts only one class. Multiple inheritance also risks inheriting two copies of A's state (fields).
  • The solution is interfaces (later). A class can implements many interfaces. If two interfaces provide conflicting default methods, the compiler forces the class to override the method and resolve the conflict explicitly (e.g. B.super.show()).

The super Keyword

this refers to the current object. super refers to the parent-class part of the current object. It has three uses:

class Student {
    String name; int age; int rollNo; int x = 4;
    Student() { }
    Student(String name, int age, int rollNo) { this.name = name; this.age = age; this.rollNo = rollNo; }
    void print() { System.out.println(name + " " + age + " " + rollNo); }
}
class EngineeringStudent extends Student {
    String college; int x = 5;                      // this x hides the parent's x

    EngineeringStudent(String name, int age, int rollNo, String college) {
        super(name, age, rollNo);                   // ③ call the parent constructor: MUST be the first line
        this.college = college;
    }
    void print() {
        super.print();                              // ② call the parent's method (it prints name, age, rollNo)
        System.out.println(college);
        System.out.println(x + " " + super.x);      // ① parent's variable: 5 4
    }
}
new EngineeringStudent("Aditya", 28, 1001, "IIT Guwahati").print();   // Aditya 28 1001 / IIT Guwahati / 5 4
  • ① super.field reaches the parent's field when the child has a same-named one. With no name clash, super. is optional.
  • ② super.method() reuses the parent's logic and then adds to it. This is the standard pattern when overriding.
  • ③ super(args) runs the parent constructor so the parent sets up its own fields. There's no need to repeat this.name = name in the child.
⭐ Interview Important: constructors and super()
• super(…) must be the first statement, the same rule as this(…). So one constructor can't contain both.
• If you don't write it, the compiler automatically inserts super();, a call to the parent's no-arg constructor. That's why the video's Student needed Student() { }: EngineeringStudent(String college) implicitly calls super(). If the parent has only a parameterized constructor, that becomes the compile error "Implicit super constructor Student() is undefined".
• Order of construction: parent first, then child. new CSEEngineeringStudent() runs the Object constructor, then Student's, then EngineeringStudent's, then CSEEngineeringStudent's.
• Like this, super can't be used in a static context.

Abstraction

⭐ Definition: Abstraction is the process of focusing on what something does while ignoring how it does it.
  • The whole human world runs on abstraction. You think of a car as drive, brake, accelerate (behaviour) and colour, type, price (data), not as 30,000 parts and combustion physics. You think of an ATM as deposit, withdraw, check balance.
  • Without abstraction, every driver would need to be an engineer, every engineer a physicist, and every physicist a mathematician. Each layer uses the layer below it without knowing its internals.
  • A refinement of "OOP simulates the real world": OOP simulates how humans perceive reality (a teacher teaches, a car drives, a button is clicked), not reality itself (cells, organs, …).
  • Abstraction says two things: ① represent only what's necessary, i.e. model the relevant parts only. ② Even for what you model, users shouldn't need to know how it's implemented. They just use it, the way a steering wheel, pedals and gearbox are the interface to a car's internals.

Two levels of abstraction in Java

LevelIdeaHow Java does it
Low-levelHide implementation detailsOrdinary (concrete) classes: c.brake() works without you reading brake()'s code
High-levelSeparate the what from the howAbstract classes and interfaces (building on inheritance)

The problem with concrete classes alone: with FuelCar fc and ElectricCar ec, each reference is tightly coupled to exactly one implementation. fc.drive() always runs FuelCar's drive. Every new kind of car needs its own variable type. What we want is one reference type, Car c, that can point to any kind of car, with c.drive() running whichever implementation the actual object has. Inheritance makes this possible (a parent reference can point to a child object), and abstract classes and interfaces formalise it.

Abstract Classes

abstract class Car {                         // has ≥1 abstract method → the class MUST be abstract
    void start() { System.out.println("Car started"); }   // concrete: shared by all cars
    abstract void accelerate();              // declared only (no body): children MUST define it
    abstract void brake();
}
class FuelCar extends Car {
    @Override void accelerate() { System.out.println("Fuel car is accelerating"); }
    @Override void brake()      { System.out.println("Fuel car is stopping"); }
}
class ElectricCar extends Car {
    @Override void accelerate() { System.out.println("Electric car is accelerating"); }
    @Override void brake()      { System.out.println("Electric car is stopping (regenerative)"); }
}

Car car = new ElectricCar();   // or new FuelCar(). Car itself can't be instantiated
car.start();                   // Car started (inherited)
car.accelerate();              // Electric car is accelerating
// new Car();                  // ✘ "Cannot instantiate the type Car"
  • An abstract method is declared but not defined (it ends with ;). Without the abstract keyword you get the compile error "This method requires a body instead of a semicolon".
  • If a class has even one abstract method, the class must be declared abstract.
  • An abstract class can't be instantiated. Otherwise new Car().accelerate() would call a method with no body.
  • A concrete subclass must implement every inherited abstract method ("The type FuelCar must implement the inherited abstract method…"), or declare itself abstract too and pass the job down the hierarchy.
  • @Override is an annotation that says "this replaces a parent method". It's optional but best practice: the compiler then errors if you mistype the signature, which would otherwise silently create a new method.
  • Not covered in the video: an abstract class can have fields, constructors (run through super(…) from the child) and fully concrete methods. It can even have zero abstract methods and still be declared abstract, just to prevent instantiation. abstract and final can't be combined on a class or method, because they contradict each other.

Interfaces

interface Car {                    // (a better name would be something like Drivable, see below)
    void start();                  // implicitly public abstract
    void accelerate();
    void brake();
}
class FuelCar implements Car {     // implements, not extends
    @Override public void start()      { System.out.println("Fuel car has started"); }
    @Override public void accelerate() { … }
    @Override public void brake()      { … }
}
Car car = new FuelCar();           // an interface type as the reference: ✔
// new Car();                      // ✘ can't instantiate an interface
  • Interface methods are implicitly public abstract, so there's no need to write abstract. That's why the implementing methods must be public: leaving it off gives "Cannot reduce the visibility of the inherited method". An overriding method can widen access, never narrow it.
  • A class extends a class, but implements an interface.
  • Classically (before Java 8), an interface contains only abstract methods: pure abstraction. Not covered in detail in the video: Java 8 added default and static methods with bodies, and Java 9 added private methods. Fields in an interface are implicitly public static final (constants). Interfaces have no constructors and no instance state.
  • The video says "an interface has nothing to do with objects". The accurate meaning: an interface isn't a blueprint of an object (it defines no state), it's a contract. It's still a type: you can have Car c references, pointing to objects of classes that implement it.
⭐ Interface = contract of capabilities / roles
"If you want to call yourself X, you must implement these methods." For example, Flyable requires fly(). Bird implements Flyable flaps its wings and Airplane implements Flyable uses engines. They're completely unrelated classes that share one capability.
Naming: capability adjectives such as Comparable, Serializable, Runnable, Flyable. (C# convention prefixes an I, e.g. ICar. Some Java teams do the same.)

⭐ Interview Important: Abstraction vs Encapsulation
• Abstraction works at the design level. It hides complexity / implementation: expose what, hide how. Tools: abstract classes, interfaces. Nothing is secret. You can open the car's bonnet, you just don't have to.
• Encapsulation works at the implementation level. It bundles data with methods and protects the data from unrestricted access. Tools: classes, private fields, getters and setters.
Correction on terms: the video pairs abstraction with "data hiding" and encapsulation with "data security". In standard terminology, data hiding belongs to encapsulation (private fields), and abstraction is implementation hiding. Short answer: abstraction hides complexity, encapsulation hides (and guards) data.

Polymorphism

Poly means many and morph means form: one thing, many forms. It shows up in two ways.

① Compile-time (static) polymorphism = method overloading

Real life: the same object reacts differently to the same command when one parameter changes. A human told to "run" goes 2 km/h normally, and 5 km/h if a dog is chasing.

class Human {
    void run()                   { System.out.println("Running at 2 km/h"); }
    void run(boolean dogBehind)  { if (dogBehind) System.out.println("Running at 5 km/h"); }
}
h.run();       // → run()
h.run(true);   // → run(boolean)   the compiler picks the method from the argument list

It's resolved at compile time. The compiler sees the arguments and binds the call to one method (static binding).

② Runtime (dynamic) polymorphism = method overriding

Real life: different objects of one family react differently to the same command in the same situation. Tell a dog, a duck and a human to "run" and each runs its own way.

abstract class Animal { abstract void run(); }
class Dog   extends Animal { void run() { System.out.println("Dog runs on 4 legs"); } }
class Duck  extends Animal { void run() { System.out.println("Duck waddles"); } }
class Human extends Animal { void run() { System.out.println("Human runs on 2 legs"); } }

Animal a;
if (type.equals("duck"))       a = new Duck();      // which object? known only when the program runs
else if (type.equals("human")) a = new Human();
else                           a = new Dog();
a.run();                                            // runs the ACTUAL object's run()

Precision: the video explains "runtime" as "because objects are created at runtime". The core reason is that the JVM looks at the real class of the object behind the reference at the moment of the call (dynamic dispatch). The compiler only checks that the reference type has such a method. That's also why Car c = new FuelCar(); can call only methods declared in Car. A FuelCar-only method needs a cast: ((FuelCar) c).refuel().

⭐ Overriding rules (not covered in the video)
• The same name and parameter list. The return type must be the same or a subtype (covariant return).
• Access can't be more restrictive than the parent's (public stays public).
• It can't throw new or broader checked exceptions.
• Inside the override, super.method() reuses the parent's version.

Why Only One Public Class per File, Named Like the File?

  • The rules: a .java file can contain many classes but at most one public top-level class, and that class's name must equal the file name (Demo.java → public class Demo). A second public class gives "The public type Sample must be defined in its own file".
  • The video's explanation: the JVM must find the class that contains main. If several classes were public, it wouldn't know which one to look in. If the public class matches the file name, the JVM can go straight from Demo.java to Demo.main(). main is public so the JVM (from outside) can reach it, and static so no object is needed.
  • In a multi-file app, only one class has the main you actually start, and you run that file: javac Demo.java then java Demo. The other files are imported into it.

Correction on the "why": the JVM doesn't search for public classes. It runs whatever class you name on the command line (java Sample works even for a non-public Sample that has a main). The real purpose of the rule is fast, predictable lookup. When code anywhere refers to a public class com.x.Demo, the compiler and class loader know it must be in com/x/Demo.java / Demo.class, without scanning every file. Non-public classes are only used inside their own package, so they don't need that guarantee. A file with no public class can have any name.

Wrapper Classes

For every primitive, Java provides a wrapper class (non-primitive) that holds that one value as an object:

Primitivebyteshortintlongfloatdoublecharboolean

int x = 10;                       // a plain value on the stack
Integer y = new Integer(10);      // an object on the heap, y is a reference (constructor deprecated since Java 9)
Integer z = Integer.valueOf(10);  // the preferred way (uses the cache, see below)
  • Why wrappers? ① Many Java APIs work only with objects, above all the Collections framework and generics: ArrayList<int> ✘, ArrayList<Integer> ✔. ② An object can carry useful methods and constants (Integer.parseInt("42"), Integer.MAX_VALUE, Character.isDigit(c)). ③ A wrapper can be null, meaning "no value".

Autoboxing & Unboxing

int x = 10;
Integer y = x;          // AUTOBOXING (primitive → wrapper). The compiler writes:  Integer y = Integer.valueOf(x);
                        //   (in old Java: new Integer(x))
Integer a = 20;         // autoboxing a literal
int b = a;              // UNBOXING (wrapper → primitive). The compiler writes:  int b = a.intValue();
System.out.println(y);  // prints 10 (println(Object) calls toString; for an Integer it gives the value)

Correction: the video says println(y) works because of unboxing. For an Integer, println actually picks the println(Object) overload, which calls y.toString(). No unboxing is involved. The output is the same either way.

Where it happens automatically:

  1. Assignments: Integer y = x; and int b = a;
  2. Method calls: passing an Integer to printInteger(int x) unboxes it, and passing an int to a method that takes Integer boxes it.
  3. Arithmetic: Integer a = 10, b = 20; int sum = a + b; unboxes both (a.intValue() + b.intValue()), adds, and gives 30.
⭐ Unboxing null → NullPointerException
Integer x = null; int y = x; compiles fine, but at runtime becomes x.intValue() on null, which throws an NPE. A primitive can't hold "no value". The same happens in arithmetic (x + 1) or in a method call that expects an int. It's a very common production bug with collections and maps.

== vs equals()

int p = 10000, q = 10000;
System.out.println(p == q);                    // true   (primitives: values compared)

Integer a = 200, b = 200;
System.out.println(a == b);                    // false  (two different objects → different references)
System.out.println(a.intValue() == b.intValue()); // true (compare the values)
System.out.println(a.equals(b));               // true   (equals compares the values)
  • == does the same thing in both cases: it compares what the two variables hold. A primitive variable is the value, so values get compared. A reference variable holds an address, so addresses get compared, i.e. "do these point to the same object?".
  • equals() compares contents. For wrappers it compares the wrapped values. It's inherited from Object (whose default is ==), and Integer overrides it. More on this in the next video.
  • Not covered in the video: if one side is a primitive, the wrapper is unboxed and the comparison is numeric. Integer a = 200; int c = 200; a == c gives true.

The Integer Cache: why 100 == 100 is true but 200 == 200 is false

Integer x = 100, y = 100;   System.out.println(x == y);   // true
Integer a = 200, b = 200;   System.out.println(a == b);   // false
  • Precision: the video says the result can differ from compiler to compiler. It doesn't. The Java spec guarantees caching for −128…127 when autoboxing. Only values outside that range are unspecified (usually not cached). The upper bound can be raised with -XX:AutoBoxCacheMax.
  • Not covered in the video: Byte, Short and Long use the same −128…127 cache, Character caches 0…127, and Boolean has just TRUE/FALSE. Float and Double aren't cached.
⭐ Rule: never compare wrapper objects with ==. Use .equals(). == "working" for small numbers is exactly what makes this bug hard to spot: tests with small values pass, and production values over 127 fail.

A conceptual view of the Integer class

public final class Integer {                  // final: can't be subclassed
    private final int value;                  // the wrapped primitive
    public Integer(int value) { this.value = value; }          // deprecated
    public static Integer valueOf(int i) { /* return the cached object if −128..127, else new */ }
    public int intValue() { return value; }   // used for unboxing (like a getter)
    public boolean equals(Object obj) { /* compare value with ((Integer) obj).value */ }
}

The real class also extends Number and implements Comparable<Integer>, and equals takes an Object parameter, because it overrides Object.equals. You'll be able to read JDK sources like this directly by the end of the series.

POJO: Plain Old Java Object

A simple class that depends on no framework (no Spring annotations, no required parent class): fields, constructors, getters and setters. It's used to model an entity, which is why these are also called model classes, e.g. one row of a student table in SQL.

class Student {                      // an anemic POJO
    private String name;
    Student(String name) { this.name = name; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
}
  • There's no strict definition. The original idea was no hardcore business logic. In practice, people add builders (the Builder design pattern) or some logic too.
  • Anemic model: only fields, constructors and getters/setters, i.e. pure data. Behaviour lives in separate service classes.
  • Rich domain model: the data plus business logic in the same class, e.g. markAttendance() inside Student. Both are still POJOs. The difference is only architectural.
  • Not covered in the video: a JavaBean is a stricter POJO: a public no-arg constructor, private fields with getters and setters following naming conventions, and usually Serializable. Modern Java (16+) also has record for immutable data carriers: record Student(String name, int age) {} generates the constructor, accessors, equals, hashCode and toString.

Video 19: Nested Classes: Static Nested, Inner, Local & Anonymous

A nested class is a class written inside another class. The enclosing one is the outer class. There are four kinds, depending on how and where the inner class is declared: static nested, inner (non-static member), local and anonymous. Official terminology groups them as static nested classes vs inner classes, where inner classes include the member, local and anonymous kinds.

Why Nest a Class?

  1. Logical grouping: some classes only make sense inside another one (a helper used only by its outer class). Nesting shows that relationship and keeps the package tidy.
  2. Better access to the outer class: a nested class can use the outer class's private members directly, with no getters or setters, because it's inside the class. (The reverse also works: the outer class can access the nested class's private members.)
  3. Encapsulation / hiding: the nested class itself can be private, which a top-level class can't be, so it's invisible outside the outer class.

1. Static Nested Class

class Outer {
    private static int x = 4;
    int y;                                         // instance (non-static) field

    static class Inner {                           // static nested class
        void fun() {
            System.out.println(x);                 // ✔ static member of Outer (even private)
            // System.out.println(y);              // ✘ "Cannot make a static reference to the non-static field y"
        }
        void show(Outer o) { System.out.println(o.y); }  // ✔ via an explicit Outer reference
    }
}

Outer.Inner inner = new Outer.Inner();             // no Outer object needed. Its full name is Outer.Inner
inner.fun();
  • It belongs to the class Outer, not to an Outer object, like any static member. That's why you create it with new Outer.Inner() without making an Outer.
  • Its name is Outer.Inner, not just Inner. The JVM finds it inside Outer, the same way Outer.x reaches a static field. (The compiled file is Outer$Inner.class.)
  • It can access only the outer class's static members directly (private ones included). For instance members it needs an explicit Outer reference, passed to a method or stored through a constructor.
  • Otherwise it's a completely normal class. It can have fields, methods, constructors, static members and any access modifiers, and it can extend a class or implement interfaces.

Correction: the video suggests a static nested class has "one shared inner object for all outer objects". "Static" doesn't make it a singleton. You can create as many Outer.Inner objects as you like. What "static" means is that each one is independent of any Outer object.

Use case: a private helper class

class BankAccount {
    public double computeInterest(double principal) {
        return InterestCalculator.calculateYearly(principal, 0.09);
    }
    private static class InterestCalculator {             // hidden from everyone outside BankAccount
        static double calculateYearly(double p, double rate)  { return p * rate; }
        static double calculateMonthly(double p, double rate) { return p * rate / 12; }
    }
}

Typical uses: a helper class for the outer class, the Builder design pattern (new Pizza.Builder().size(…).build()), request/response DTOs (Spring Boot, later), and whenever you need static members in a nested class. Static nested is the most commonly used of the four.

2. Inner Class (non-static member class)

class Outer {
    int x = 10;
    class Inner {                                  // no "static"
        int x = 20;                                // shadows Outer's x
        void fun() {
            System.out.println(x);                 // 20 (Inner's own)
            System.out.println(Outer.this.x);      // 10 (the outer instance's x)
        }
    }
}

Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();             // needs an Outer object: outer.new Inner()
// Outer.Inner inner = new Outer().new Inner();    // one-liner, if you don't need the Outer reference
inner.fun();
  • An inner object is tied to an Outer object, so you can't create it without one. The syntax outer.new Inner() follows the usual dot-operator logic: go into that outer object, then create its Inner.
  • Every inner object carries a hidden reference to its outer object, which the compiler adds (Outer.this). That's why it can access all outer members, static and instance, private included. A plain x (with no shadowing) is compiled as Outer.this.x.
  • In memory, the inner object is a separate heap object. It's not inside the outer object. It only points to it.
  • If the inner class has a field with the same name as the outer's, the inner one shadows it. Use Outer.this.x for the outer field.

Correction: the video says every outer object "has its own inner object". Inner objects are created only when you write outer.new Inner(). One outer object can have zero, one or many inner objects, and each points back to its creator.

⭐ Static members inside an inner class
Before Java 16, an inner (non-static) class couldn't declare static members, except compile-time constants such as static final int K = 5;. The reason was ambiguity: a static field is "one per class", but the inner class itself exists "per outer object". Should x be shared across all Outer objects, or be one per Outer? Java avoided the question by forbidding it. If you needed statics, you made the nested class static.
Since Java 16 (JEP 395, which came with records), inner classes may declare static members, and they're simply per class. That's why the video's IDE shows no error.
⭐ Prefer static nested unless you need the outer instance (not covered in the video)
The hidden Outer.this reference keeps the outer object alive as long as the inner object is reachable. For example, a long-lived listener object can stop a big outer object from being garbage-collected, which is a classic memory leak (well known in Android). Rule of thumb: if the nested class doesn't use the outer's instance members, make it static.

3. Local Class

A class declared inside a block: a method, constructor, if, loop, switch, or even a static block. It exists only inside that block, and it's rarely used in production.

class Outer {
    private int x = 4;
    void greet() {
        int y = 5;                                  // a local variable of greet()
        class Local {                               // local class: visible only inside greet()
            void sayHello() {
                System.out.println(x);              // ✔ outer members (instance/static, private too)
                System.out.println(y);              // ✔ only because y is effectively final
            }
        }
        Local local = new Local();
        local.sayHello();
        // y++;                                     // ✘ would break it: "Local variable y defined in an
                                                    //    enclosing scope must be final or effectively final"
    }
}
  • It follows the same access rules as an inner class, since it's non-static. In a static method, only the outer's static members are reachable.
  • Not covered in the video: a local class can't have access modifiers (no public/private) and can't be static. Since Java 16, local records, enums and interfaces are allowed too.
⭐ The "effectively final" rule, and why it exists
A local (or anonymous) class may use a local variable of the enclosing method only if that variable is final or effectively final, i.e. never modified after its initial assignment.
Why: the local variable lives on the stack and disappears when greet() returns, but the Local object lives on the heap and can outlive the method (e.g. if it's returned as an Object and called later). So the compiler copies the variable's value into a hidden field of the Local object (capture by value). If y could change later (y++), which value would the copy hold? The old one, or the new one? Java removes the ambiguity by forbidding changes.
The same rule applies to lambdas. (Before Java 8, the variable had to be explicitly declared final. "Effectively final" was added in Java 8.)

The video's aside explains how a local object can escape: the method's return type can't be Local, because that name is invisible outside the method. It can be Object, the root class of all classes, which gets its own lecture: Object greet() { …; return new Local(); }.

4. Anonymous Class

A class with no name, declared and instantiated in a single expression. It's for a one-off override you need in exactly one place.

class Person {
    void introduce() { System.out.println("Hi, I am a person"); }
}

// Without an anonymous class: a whole named subclass for a single use
// class Guest extends Person { @Override void introduce() { System.out.println("Hi, I am a guest"); } }

Person p2 = new Person() {                       // ← no ';' here: { starts the anonymous subclass of Person
    String name = "Aditya";                      // fields are allowed
    void greet() { System.out.println("Hello"); } // extra methods are allowed
    @Override
    void introduce() {
        greet();                                 // extra members can be used only from inside
        System.out.println("Hi, I am " + name);
    }
};
p2.introduce();       // Hello / Hi, I am Aditya
// p2.greet();        // ✘ "The method greet() is undefined for the type Person"
// p2.name;           // ✘ same reason
  • new Person() { … } creates an unnamed subclass of Person and one object of it. It can extend a class or implement one interface: new Runnable() { public void run() { … } }.
  • Its extra methods and fields can't be called through p2, because the reference type is Person (normal polymorphism rules). They're only useful as helpers inside the overridden method.
  • No constructors: a constructor must have the class's name, and this class has none. Not covered in the video: you can still ① pass arguments to the parent's constructor, new Person("x") { … }, and ② use an instance initializer block { … } inside the body for setup.
  • The same access rules apply as for inner classes. Declared inside a method it's a local anonymous class, so the effectively final rule applies too. Compiled files are named like Demo$1.class.
  • If you need the same behaviour repeatedly, write a real named class instead. For one-method interfaces, modern Java uses lambdas instead: Runnable r = () -> System.out.println("run");.

Video 20: Standard Input/Output: System.out, Streams, System.in.read(), BufferedReader, Scanner

Types of I/O, by source or destination: console (keyboard in, screen out), file, network (API calls, covered with Spring Boot) and memory (buffers). This lecture covers console I/O. File I/O gets its own lecture.

Decoding System.out.println("Hello")

PartWhat it is
SystemA class (capital S) in java.lang, which is auto-imported into every file. That's why no import is needed.
outA public static final PrintStream field of System. Static, so it's accessed through the class name. Final, so it can't be reassigned by your code.
println(…)An instance method of PrintStream, called on the out object. It prints its argument and then a newline.
  • PrintStream methods: println (with a newline), print (no newline) and printf (formatted output, e.g. System.out.printf("%s is %d, %.2f%n", name, age, gpa);). println is overloaded for every type (int, double, char[], Object, …).
  • If out weren't static, you'd need System s = new System(); s.out.println(…). Being static saves you that.
  • Not covered in the video: the source says out = null. The JVM fills it in natively during startup. That's also how System.setOut(…) can redirect it despite final.

System.err

int age = -3;
if (age < 0) System.err.println("Invalid age");   // error channel
else         System.out.println("Valid");          // normal output
  • err is another PrintStream, the same type as out, but it writes to the OS's standard error stream, not standard output. That separates normal output from errors: IDEs show it in red, log tools can treat it differently, and it can be redirected separately (java App > out.txt 2> err.txt).
  • Because they're two independent streams, lines from out and err may appear in an interleaved order on the console. Real applications use logging libraries rather than either one.

Streams

A stream is a flow of data, like water through a pipe. Java I/O is stream-based, so the same model works whether the data comes from the console, a file, the network or memory.

  • InputStream: data flows into the program (reading). OutputStream: data flows out of the program (writing).
  • Both are abstract classes in java.io. InputStream declares read() and OutputStream declares write(). Subclasses decide where the data comes from or goes to.
  • These are byte streams: data moves as a sequence of bytes.

Input Level 1: System.in.read()

import java.io.IOException;
public static void main(String[] args) throws IOException {   // read() can throw a checked IOException
    int x = System.in.read();            // type "A" → 65 (the byte value)
    System.out.println((char) x);        // cast back → A
}
  • The keyboard sends characters into an OS input buffer as bytes (their ASCII codes): typing Aditya⏎ gives 65 100 105 116 121 97 10 (10 is \n, the newline escape sequence. \t is a tab).
  • read() reads ONE byte at a time. Typing "Aditya" and calling it once gives only A. The rest stays in the buffer. Reading a whole word means a loop:
String s = ""; int c;
while ((c = System.in.read()) != '\n') s += (char) c;   // one OS call per character → slow and clumsy
  • Not covered in the video: why does read() return an int, not a byte? It returns 0–255 for data, and −1 at end of stream. A byte can't represent 256 data values plus a separate −1 signal.
  • Also: on Windows, Enter produces \r\n, so the loop above would pick up a stray \r. And a non-ASCII character (e.g. Hindi text) is several bytes in UTF-8, so reading bytes one by one breaks it. That's one reason character streams exist.
  • A Java char is 2 bytes (UTF-16), but an ASCII key arrives as 1 byte of input. So reading one byte is enough for a plain English letter.

Input Level 2: InputStreamReader + BufferedReader

import java.io.*;
public static void main(String[] args) throws IOException {
    InputStreamReader isr = new InputStreamReader(System.in);   // bytes → characters
    BufferedReader br = new BufferedReader(isr);                // buffering + readLine()
    // usual one-liner: BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
    String name = br.readLine();          // "Aditya Tandon" (the whole line)
    int age = Integer.parseInt(br.readLine());   // only Strings come back, so parse manually
}
  • Reader is the abstract base for character streams (the counterpart of InputStream for bytes).
  • BufferedReader reads a big chunk (8,192 chars by default) from the OS buffer into its own buffer in program memory. Later reads come from memory, not from an OS call per character. It's much faster, and it gives you readLine().
  • BufferedReader works on characters, but System.in gives bytes, so they aren't directly compatible. InputStreamReader is the bridge: it decodes bytes into characters (using a charset such as UTF-8), which fixes the multi-byte-character problem too.
  • The constructors show the chain: InputStreamReader(InputStream in) and BufferedReader(Reader in). You pass the isr, which is a Reader.

Correction: the video says InputStreamReader "is a subtype of BufferedReader". It isn't. Both extend Reader as siblings. That's why an InputStreamReader can be passed where BufferedReader's constructor expects a Reader. This pattern of wrapping one stream inside another to add behaviour is the Decorator design pattern.

Limitations: ① it returns only Strings, so numbers need Integer.parseInt(s) / Double.parseDouble(s), which throw NumberFormatException on bad input. ② The setup is verbose, and you have to handle IOException. Not covered in the video: readLine() returns null at end of input.

Input Level 3: Scanner (Java 1.5)

import java.util.Scanner;                 // java.util, not java.io. No "throws IOException" needed

Scanner sc = new Scanner(System.in);      // keyboard
String line = sc.nextLine();              // whole line up to Enter: "Aditya Tandon"
String word = sc.next();                  // next token only: "Aditya"
int age     = sc.nextInt();               // parsed for you
double gpa  = sc.nextDouble();
boolean ok  = sc.nextBoolean();           // also nextLong, nextFloat, nextByte, nextShort, nextBigDecimal…

// other sources:
// new Scanner(new File("temp.txt"))      // file (covered in file I/O)
// new Scanner("10 20 30")                // a String
  • It's a utility class outside the InputStream and Reader hierarchies. It wraps them (internally it reads through a Readable source) and adds conveniences.
  • It works by tokenization: input is split into tokens on a delimiter (whitespace by default). "Hello I am Aditya" gives 4 tokens. next() returns one token, and nextLine() returns the rest of the line.
⭐ Classic Scanner trap: nextInt() followed by nextLine() (not covered in the video)
int age = sc.nextInt(); String name = sc.nextLine(); gives name = "". nextInt() reads 28 but leaves the newline in the buffer, and nextLine() immediately consumes that empty rest of line. Fix: call an extra sc.nextLine(); after nextInt(), or read every line with nextLine() and parse it yourself. Also, nextInt() on input like "abc" throws InputMismatchException.
